Functions: reusable code

A function is a named, reusable piece of code. You write it once and use it as many times as you like. Functions are how every real program is organized, and they're where TypeScript starts to really shine.

In this lesson you will

  • Create (define) a function and run (call) it.
  • Pass information in with parameters.
  • Get a result back with return, and understand how that differs from console.log.
  • Give parameters default values.
  • Type a function's inputs and output in TypeScript.

About 50 minutes. This is one of the most important lessons in the course.

Why functions?

You've already been using functions: console.log(), Math.round(), Number(). Someone else wrote the code inside them, gave it a name, and now you can use it without knowing how it works. Now you'll write your own.

AnalogyA function is like a kitchen appliance. A toaster has a slot to put bread in (the input), does its job inside (you don't need to know how), and gives you toast (the output). You can use it again and again, with different bread each time.

Defining and calling a function

There are two separate steps here:

  2. Calling the function (lines 6–7). Writing its name with () runs the body. Each call runs the whole body again.

Function names follow the same rules as variable names (camelCase). Because functions do things, they're usually named with a verb: sayHello, calculateTotal, showMenu.

Parameters: giving a function input

A function that always does exactly the same thing is limited. Parameters let you hand it different information each time you call it:

name in the parentheses is a parameter: a variable that only exists inside the function. Each time you call greet, the value you put in the parentheses (called an argument) is placed into name. On the first call name is "Ada", on the second it's "Grace".

Functions can have several parameters, separated by commas. Arguments are matched up by position: first to first, second to second.

The last call has its arguments in the wrong order, and JavaScript happily prints nonsense. Keep that in mind; TypeScript fixes it at the end of this lesson.

return: getting a result back

So far our functions print things. But most functions are more useful when they calculate a value and hand it back so the rest of your code can use it. That's what return does:

When JavaScript reaches return, the function stops, and the call double(21) is replaced by the returned value, 42. That's why you can store it in a variable, add two calls together, or pass it to another function.

Analogyconsole.log inside a function is like a calculator that shows the answer on its screen. You can see it, but you can't do anything else with it. return is like the calculator handing you a slip of paper with the answer, which you can keep and use in the next calculation.

Variables inside functions stay inside

Parameters and variables created inside a function only exist while the function runs, and can't be seen from outside (the same block scope rule as if and loops):

This is a good thing. You can use names like total or result inside every function without them clashing with each other.

Common mistakes
  • Forgetting to call it: sayHello without () doesn't run anything.
  • Printing instead of returning: if you need to use the result, the function must return it.
  • Forgetting return: function double(n) { n * 2; } calculates the answer and throws it away. It returns undefined.
  • Code after return never runs.
  • Arguments in the wrong order: they're matched by position, not name.

In TypeScript

Functions are where TypeScript is most valuable. A function is a promise: "give me these kinds of inputs and I'll give you this kind of output". TypeScript lets you write that promise down, and then checks every call.

Should you write return types?It's optional, since TypeScript infers them. Many teams write them on important functions anyway, because it documents the promise and catches mistakes inside the function, not just at the call site. In this course we'll write them when they help.

Recap

  • Define with function name(params) { ... }; call with name(args).
  • Parameters are the input variables; arguments are the values you pass, matched by position.
  • return hands a value back and stops the function. No return means undefined.
  • Prefer returning values over printing inside functions.
  • Defaults: function f(x = 10). Variables inside a function stay inside.
  • In TypeScript, type every parameter (n: number), optionally the return (): string). Use void for "returns nothing" and ? for optional parameters.

Check your understanding

What's the difference between a parameter and an argument?A parameter is the name in the function definition (n in function double(n)). An argument is the actual value passed in a call (21 in double(21)).
What does a function return if it has no return statement?undefined. In TypeScript its return type is void.
Why does TypeScript require parameter types, but not variable types?A variable usually gets a value right away, so its type can be inferred. A parameter's value only arrives when someone calls the function, so TypeScript needs you to say what's allowed.
