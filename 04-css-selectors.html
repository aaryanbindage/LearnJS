Lesson 4 — Selectors, cascade & specificity

CSS is a set of rules: pick elements with a selector, then set properties. Most CSS bugs are really "which rule wins?" bugs, so learn the cascade early.

Pseudo-classes and pseudo-elements

Pseudo-classes select by state or position: :hover :focus :focus-visible :active :checked :disabled :invalid :first-child :last-child :nth-child(2n+1) :not() :is() :where() :has().

Pseudo-elements create or target a part of an element: ::before ::after ::first-line ::first-letter ::placeholder ::selection.

The cascade: how conflicts resolve

When several rules set the same property on one element, the browser decides in this order:

  1. Origin & importance: !important beats normal (avoid it).
  2. Cascade layers (@layer): later layers beat earlier ones for normal rules.
  3. Specificity: more specific selector wins.
  4. Source order: last rule wins.

Inheritance

Text properties (color, font-*, line-height) inherit from the parent. Box properties (border, margin, padding) do not. Force behavior with inherit, initial, unset, revert.

Good habits

  • Style with classes; keep specificity low and flat.
  • Name by purpose (.card-title), not looks (.red-text). BEM (.card__title--large) is optional.
  • Avoid !important and avoid ids for styling.

Exercises

  1. Without running it, find the winner among #a .b p, .b .c .d p and div p.x.y. Then verify in DevTools (struck-out rules in the Styles pane).
  2. Zebra-stripe a table with :nth-child and highlight rows on hover.
  3. Add an arrow to external links with a[href^="http"]::after.
  4. Use :has() to color a label red when its sibling input is :invalid.
  5. Create a specificity conflict, then resolve it without !important.

Checkpoint

Why is !important a smell?It escapes the normal specificity rules, so the only way to override it is another !important. Styles become an arms race.
What does :where() do for library authors?It adds zero specificity, so your defaults are trivially overridable by users.
