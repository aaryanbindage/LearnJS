Classes & this

When you need many objects of the same kind, each with its own data and the same abilities, a class is a blueprint for making them. This lesson covers classes, the keyword this, and the extra safety TypeScript adds to them.

In this lesson you will

  • Understand this inside methods.
  • Write a class with a constructor, properties and methods, and create objects from it with new.
  • Build on a class with extends and super.
  • Hide internal details with private fields.
  • Use TypeScript's private, readonly, and implements.

About 50 minutes.

Methods and this

In the objects lesson you put functions inside objects. Often a method needs to use the object's own data. Inside a method, the keyword this means "the object this method was called on":

When you call dog.bark(), the thing before the dot is dog, so inside bark, this is dog, and this.name is "Rex".

Now imagine you need 50 dogs. Copying that object 50 times, methods and all, would be silly. That's what classes are for.

Your first class

AnalogyA class is like a cookie cutter, and objects are the cookies. The cutter defines the shape once; each cookie made from it is separate, and can have different toppings (data).

Let's go through it:

  • class Dog { ... } defines the blueprint. Class names use PascalCase.
  • constructor(name, breed) is a special method that runs once whenever a new dog is made. Its job is to set up the new object's properties, using this.
  • bark() and learnTrick() are methods that every dog shares. (Note: no commas between methods in a class, unlike in an object.)
  • new Dog("Rex", "beagle") creates a new object from the blueprint, runs the constructor with those arguments, and gives you the object. An object made from a class is called an instance of that class.
Try itAdd a method describe() that returns a string like "Rex is a beagle who knows 1 trick(s)", and print it for both dogs.

Inheritance: extends

A class can be based on another class. It gets all the parent's properties and methods, and can add its own or replace some:

  • extends Animal: a Cat is a kind of Animal.
  • super(name) calls the parent's constructor. In a child class constructor, you must call it before using this.
  • instanceof checks whether an object was made from a class (or a child of it). You used this in the DOM lesson: HTMLInputElement is a class that extends HTMLElement.
Use inheritance sparinglyLong chains (Animal → Mammal → Pet → Dog → …) become hard to change. One level is usually plenty. Many modern codebases, including React, use very little inheritance.

Static members

A static method or property belongs to the class itself, not to each instance. You've used one: Math.max and Number.isNaN work like this.

The this trap

this is set by how a function is called: it's the thing before the dot. If you pass a method somewhere as a callback, there's no dot anymore when it's called, so this is lost:

This matters most for event handlers: button.addEventListener("click", c.increment) breaks for the same reason. Wrap it: () => c.increment(). Arrow functions don't have their own this; they use the this from where they were written, which is usually what you want.

Classes or plain objects?

You don't need classes for everything. A good rule:

  • Plain objects and functions for data: users, products, settings. Most data in web apps is plain objects (that's what comes back from servers, too).
  • Classes when something has data that must be protected by rules (a bank account), or you need many objects with the same behaviour and internal state (enemies in a game, a 3D scene in Three.js).
Common mistakes
  • Forgetting new: Dog("Rex") throws "Class constructor cannot be invoked without 'new'".
  • Forgetting this. inside a method: name on its own refers to some other variable, not the property.
  • Commas between class methods (that's object syntax).
  • Passing a method as a callback and losing this. Wrap it in an arrow function.
  • Using this before super() in a child constructor.

In TypeScript

Declaring properties

In TypeScript, a class must declare its properties and their types up front. (In JavaScript you could just assign this.anything in the constructor.)

Every rule you learned about functions applies to methods and constructors too.

private vs #privateTypeScript's private is only checked by TypeScript; once compiled to JavaScript, the property is accessible. JavaScript's #balance is enforced when the code runs. Both are fine. private is more common in TypeScript code you'll read; # is the stricter choice.

Recap

  • Inside a method, this is the object before the dot.
  • class X { constructor() {...} method() {...} } is a blueprint; new X() makes an instance.
  • #field is private; get prop() is read like a property; static belongs to the class.
  • extends builds on a class; call super() first in the constructor.
  • Passing a method as a callback loses this: wrap it, () => obj.method().
  • TypeScript: declare property types; use private, readonly, parameter properties, and implements.

Check your understanding

What does the constructor do?It runs once each time you call new, and sets up the new instance's properties.
Why does setTimeout(obj.method, 100) break when the method uses this?When setTimeout later calls the function, there's no object before the dot, so this is undefined. Use setTimeout(() => obj.method(), 100).
What does implements do in TypeScript?It makes TypeScript check that the class has everything the interface (or type) requires.
