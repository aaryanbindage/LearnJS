Lesson 29 — Routing & app architecture

Real apps have multiple pages, shareable URLs and a folder structure that scales.

Client-side routing with React Router

A single-page app (SPA) swaps components when the URL changes, without full page reloads. Install: npm install react-router-dom (v6/v7 API shown).

  • Use <Link>/<NavLink> (not <a href>) for internal navigation.
  • Put shareable state in the URL: filters, sort, page, tab (useSearchParams).
  • Lazy-load route code: { path: "admin", lazy: () => import("./routes/Admin") } to shrink the initial bundle.
  • Host SPAs with a fallback so unknown paths serve index.html (Netlify _redirects, Vercel rewrites).
  • Consider Next.js or React Router framework mode if you need server rendering, SEO, or server-side data.

Project structure that scales

  • Feature folders keep related code together; features import from components/ and lib/, not each other's internals.
  • Container vs presentational: separate "gets data/handles logic" from "renders UI from props".
  • Co-locate tests and styles with the component. Use CSS Modules (Button.module.css), Tailwind, or CSS-in-JS consistently.
  • Centralize the API layer (lib/api.js) so URLs, headers and error handling live in one place.
  • Environment variables: VITE_API_URL in .env, read via import.meta.env.VITE_API_URL. Never put secrets in frontend code.
