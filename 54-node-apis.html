Lesson 54 — Node.js & building HTTP APIs

Time to build the other half of the web. You already know JavaScript, so Node.js lets you write servers in the same language. Run every example locally with node (these need a terminal, not the browser sandbox).

What Node is

  • A JavaScript runtime (V8 + libuv) outside the browser: file system, network, processes. No DOM or window.
  • Same single-threaded event loop model: non-blocking I/O makes it excellent at handling many concurrent connections. CPU-heavy work blocks everyone, so use worker threads or a queue for that.
  • ES modules: set "type": "module" in package.json and use import. Use the node: prefix for built-ins.
  • Alternatives with similar APIs: Bun and Deno. Everything here applies.

Architecture of a clean API

  • Validate all input at the edge with schemas; validate config at startup (fail fast).
  • Separate layers so business logic is testable without HTTP.
  • Consistent errors: { error, code, details } with correct status codes.
  • Structured logging (pino, JSON lines) with a request id; never log secrets.
  • Pagination (?limit=20&cursor=…), filtering, sorting; idempotency keys for payments; rate limiting.
  • Twelve-factor: config from env, stateless processes, logs to stdout, disposable processes.

Background work and other concerns

  • Queues/jobs (BullMQ + Redis, pg-boss): emails, image processing, webhooks, anything slow or retryable.
  • File uploads: stream to object storage (S3/R2) with presigned URLs; never keep large files in memory.
  • Caching: HTTP caching, in-memory (LRU), Redis; invalidate carefully.
  • Scaling: stateless processes behind a load balancer; keep state in DB/Redis. Cluster/worker threads for CPU use.
  • Serverless / edge functions (Vercel, Cloudflare Workers, AWS Lambda) are an alternative to long-running servers: great for spiky or simple workloads.
