Lesson 42 — Tailwind CSS & utility-first design

Tailwind gives you small single-purpose classes (p-4, flex, text-lg) that you compose in markup. It is the most widely used CSS approach in modern React projects, so you need to be fluent in it, and to know when not to use it.

Why it works

  • No naming: you stop inventing class names.
  • Constrained design system: spacing, colors and sizes come from a scale, so UIs look consistent.
  • Local changes: editing a component's classes can't break another page.
  • Small CSS: only classes you use are generated (the file stops growing).

Costs: long class lists, a learning curve for the vocabulary, and you must still understand CSS. Tailwind is a way of writing CSS, not a replacement for knowing it.

Managing long class lists

  • Extract components, not CSS classes. Repeat a pattern? Make a React component, not an @apply rule.
  • Sort classes automatically with prettier-plugin-tailwindcss.
  • Never build class names dynamically (`text-${color}-500`): the scanner can't see them. Use complete strings or a lookup map.

Checkpoint

Why can't I build `text-${color}-500` dynamically?Tailwind generates CSS by scanning source for complete class names. A string assembled at runtime never appears in the source, so no CSS is generated.
Is Tailwind "just inline styles"?No. It supports media queries, pseudo-classes, dark mode, a constrained design scale and small output CSS, none of which inline styles can do.
