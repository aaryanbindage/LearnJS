Lesson 26 — Effects & data fetching

Rendering must be pure. Effects are the escape hatch for synchronizing with things outside React: the network, timers, the DOM, subscriptions.

useEffect

Dependency arrayRuns…
useEffect(fn)after every render (rarely what you want)
useEffect(fn, [])after mount only (and cleanup on unmount)
useEffect(fn, [a, b])after mount and whenever a or b change

Think of an effect as "keep X in sync with these values", not as "do this on mount". List every reactive value you read inside it in the dependencies (the eslint-plugin-react-hooks rule enforces this). In development StrictMode mounts, unmounts and mounts again to verify your cleanup works.

Fetching data

Race conditionsClick quickly between users: without the AbortController cleanup, a slow earlier response can arrive late and overwrite the correct one. Cleanup is what fixes it.

You might not need an effect

  • Derived data → compute during render. Not useEffect(() => setFiltered(...), [list]).
  • Responding to a user event → do it in the event handler, not in an effect.
  • Resetting state when a prop changes → use key.
  • Expensive calculation → useMemo.

Valid uses: fetching (better via a library), subscriptions (addEventListener, WebSocket), timers, imperative widgets (maps, WebGL canvas!), analytics, syncing with localStorage.

Use a data library in real apps

Frameworks like Next.js and React Router (data APIs) let the server load data before rendering. Hand-written fetch-in-effect is best learned once, then replaced by these.

  3. Build a debounced search that queries an API; avoid stale results with AbortController.

Checkpoint

Why does my effect run twice in development?StrictMode double-invokes mount/unmount/mount to ensure your effect cleans up properly. It doesn't happen in production.
What goes in the dependency array?Every prop, state, or derived value from the component scope that the effect reads.
