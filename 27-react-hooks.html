Lesson 27 — Refs, reducers, memoization & custom hooks

The rest of the everyday hooks, and how to package your own logic into reusable hooks.

useRef

A ref is a box ({ current }) that persists across renders; changing it does not trigger a re-render. Two uses: reaching DOM nodes, and storing mutable values (timer ids, previous values, Three.js objects!).

Don't read or write ref.current during render (except lazy init). Use it in handlers and effects.

useReducer

When state updates are many or interdependent, centralize them in a pure reducer: (state, action) => newState. It's easier to test and reason about.

Memoization: useMemo, useCallback, memo

By default, when a component re-renders, all its children re-render. That's usually fine and fast. Memoization is an optimization for measured problems, not a default.

Rule of thumbDon't memoize until profiling (React DevTools Profiler) shows a real cost. useCallback only helps if the function is passed to a memo'd child or used as an effect dependency. React 19's React Compiler can add most of this automatically.

Custom hooks

A custom hook is just a function starting with use that calls other hooks. It lets you share stateful logic (not state itself: each caller gets its own state).

Other built-ins worth knowing: useLayoutEffect (measure DOM before paint), useId, useTransition/useDeferredValue (keep UI responsive during heavy updates), useSyncExternalStore (subscribe to external stores), useImperativeHandle (rare), and in React 19: use, useActionState, useOptimistic.

Exercises

  1. Rewrite your todo app with useReducer and write unit tests for the reducer alone.
  2. Build usePrevious(value), useOnClickOutside(ref, handler), useMediaQuery(query), useFetch(url).
  3. Auto-focus an input when a modal opens, and return focus to the trigger when it closes.
  4. Build a stopwatch with useRef for the interval id and performance.now() for accuracy.
  5. Profile a list of 5,000 items with a slow child; fix it using memo and stable props, and measure before/after.

Checkpoint

State vs ref?State changes trigger re-renders and are used for anything shown on screen. Refs hold mutable values that don't affect rendering.
When is useReducer better than useState?Many related fields, complex transitions, or when the next state depends on several actions. It centralizes logic into a testable pure function.
