The DOM: changing the page with code

Everything so far has happened in the console. Now JavaScript meets the web page. In this lesson you'll find elements on a page, change their text and styles, and build new elements from your data. This is where HTML, CSS and JavaScript finally come together.

In this lesson you will

  • Change text, classes, styles and attributes.
  • Create new elements and add them to the page, including a list built from an array.
  • Use TypeScript's DOM types: HTMLElement | null, HTMLInputElement and friends.

What is the DOM?

When a browser loads your HTML, it doesn't keep it as text. It builds a tree of objects in memory, one object for every element. That tree is called the DOM (Document Object Model). JavaScript can read and change this tree, and whenever it does, the browser updates what's on screen.

As a tree, that looks like this: body has two children, h1 and ul; ul has two li children. Each box in the tree is an object with properties (like its text) and methods (like "add a child").

The whole tree is available in JavaScript as a global object called document.

How the editors work in this lessonSome editors below come with a small web page. You'll see it in the Page panel before you run anything. When you press Run, your code changes that page. The HTML of the page is shown in the lesson text just above each editor, so you know what's on it.

Finding elements

Before you can change something, you have to find it. document.querySelector() takes a CSS selector, exactly like the ones you wrote in the CSS lessons, and returns the first element that matches.

The page for the next editor contains:

MethodReturns
document.querySelector(sel)the first matching element, or null if none
document.querySelectorAll(sel)a list of all matches (possibly empty)
document.getElementById("title")the element with that id (no #), or null

Pay attention to "or null". If nothing matches, querySelector gives you null, and using it will crash. TypeScript will make sure you handle that, as you'll see at the end of this lesson.

textContent vs innerHTMLThere's also innerHTML, which treats the text as HTML: el.innerHTML = "<b>bold</b>" creates a real <b> element. It's handy, but never use it with text that came from a user. If someone types <img src=x onerror="..."> into your comment box, innerHTML would run their code on your page. This attack is called XSS. Use textContent for anything a user typed.

Changing classes and styles

The best way to change how something looks is to add or remove a CSS class, and let your stylesheet do the styling. Every element has a classList with methods for this. (This page has a .highlight class that makes a yellow background, and .hidden that hides things.)

You can also set styles directly with the style property. CSS property names with dashes become camelCase: background-color → backgroundColor.

Direct styles are fine for values that are calculated (like a position from a game). For "states" like active, hidden or selected, prefer classes.

Where to put your script

A script can only find elements that already exist. If your <script> runs before the browser has read the HTML below it, querySelector returns null. The simple fix is the defer attribute, which waits until the whole page has been read:

Common mistakes
  • Forgetting the # or .: querySelector("title") looks for a <title> tag, not id="title".
  • Using the result of querySelector without checking: if nothing matched, it's null and you get "Cannot read properties of null".
  • Script runs too early: use defer.
  • Treating querySelectorAll like one element: it's a list. Loop over it.
  • Forgetting form values are strings: input.value is always a string. Use Number(input.value) for math.

Recap

  • The DOM is the browser's tree of objects for your HTML, available as document.
  • Find elements with querySelector (first match or null) and querySelectorAll (all matches), using CSS selectors.
  • Change content with textContent (safe) rather than innerHTML for user text.
  • Change looks with classList.add/remove/toggle; set style for calculated values.
  • Create with createElement, attach with append, delete with remove. Build the page from your data.
  • TypeScript: querySelector returns Element | null. Check for null; use tag selectors, <HTMLInputElement> or instanceof to get specific types.

Check your understanding

What does querySelector return when nothing matches?null. That's why its TypeScript type is Element | null.
Why use textContent instead of innerHTML for user input?innerHTML turns text into real HTML, so a user could inject code (XSS). textContent always treats it as plain text.
Why does TypeScript say .value doesn't exist on the result of querySelector("#email")?Selecting by id could match any kind of element, so the type is the general Element. Tell TypeScript it's an input with querySelector<HTMLInputElement>, or check with instanceof HTMLInputElement.
