Objects: grouping related data

A user has a name, an email and an age. A product has a title, a price and a stock count. Objects let you keep all the facts about one thing together, under one name. Along with arrays, they're how almost all data in JavaScript is shaped, and describing their shape is TypeScript's main job.

In this lesson you will

  • Create objects, and read and change their properties.
  • Put functions inside objects (methods).
  • Combine objects and arrays: lists of objects, objects containing lists.
  • Loop over an object's keys and values.
  • Describe object shapes in TypeScript with type and interface, including optional properties.

Why objects?

Imagine storing information about a user with separate variables:

That works for one user. For two, you'd need user2Name, user2Email... and nothing ties them together. An object groups them into a single value:

  • An object is written with curly braces { }.
  • Inside, each line is a property: a key (the name, like name), a colon, then the value.
  • Properties are separated by commas. A comma after the last one is allowed, and makes adding lines easier.
AnalogyAn array is a row of numbered lockers. An object is a filing cabinet with labelled drawers: "name", "email", "age". You find things by label, not by position.

Use an array for a list of similar things in order (all the users). Use an object for the different facts about one thing (one user).

Common mistakes
  • = instead of : inside an object: it's { name: "Ada" }, not { name = "Ada" }.
  • Missing commas between properties.
  • Using a variable with the dot: user.field looks for a key named "field". Use user[field].
  • Typos in keys: user.nmae is just undefined in JavaScript, with no error. (TypeScript fixes this.)

In TypeScript

This is the heart of TypeScript. Most of the bugs in real JavaScript programs are about objects: a misspelled property, a missing field, a value of the wrong type. TypeScript tracks the exact shape of every object.

Naming a shape with type

When the same shape is used in several places, give it a name with a type alias. Type names are written in PascalCase (capital first letter):

Read type User = { ... } as "from now on, User means an object with these properties". The error on grace says Property 'age' is missing. In the type, properties are separated by semicolons (commas also work).

Optional properties

Some properties aren't always there. Mark them with ?:

Hover over description: its type is string | undefined. TypeScript won't let you call string methods on it until you've dealt with the "might be missing" case. The ?. in pen.description?.toUpperCase() is called optional chaining: "if this is missing, stop and give undefined instead of crashing". You'll learn the full set of tools for this in the Union types lesson.

type or interface?For describing an object, they do the same job, and you'll see both in real code. Small differences matter only in advanced situations. A simple rule: pick one style for your project and stay consistent. This course mostly uses type, because it can also describe things that aren't objects (like the "red" | "yellow" | "green" type you saw earlier).

Recap

  • An object groups named properties: { name: "Ada", age: 36 }.
  • Read with obj.key, or obj[variable] when the key is in a variable. Missing keys give undefined.
  • A function stored on an object is a method.
  • Arrays of objects are the most common data shape. Read paths like products[0].name left to right.
  • Object.keys / values / entries let you loop over an object. { ...obj } copies.
  • TypeScript: type User = { name: string; age?: number }. ? = optional, readonly = can't change, User[] = array of them, Record<string, number> = dictionary.

What's the difference between user.key and user[key]?user.key looks up a property literally named "key". user[key] looks up the property whose name is stored in the variable key.
