Recommended IDEs, extensions & tools

Your editor is the tool you'll spend thousands of hours in. Pick one good setup, learn it deeply, and resist constant switching. Products and prices change, so confirm current details on each tool's website.

My recommendation

Short answerUse VS Code. It is free, has the largest extension ecosystem, and the best support for everything in this course (HTML, CSS, JS/TS, React, Node, GLSL). If you want AI built into the editor, Cursor is a VS Code fork with the same extensions and keybindings, so switching later costs you almost nothing.

A note on AI assistants while learning

ImportantAI can make you faster, but it can also stop you from learning. Through Parts 1–5, type the code yourself and turn inline completions off. Use AI as a tutor ("explain why this fails", "review my solution") rather than a code generator. From Part 6 onward, AI becomes a legitimate productivity tool, but you must still be able to read, justify and debug every line it writes. Treat its output like a pull request from a confident junior developer.
  • Good uses: explaining errors and unfamiliar code, generating test cases, reviewing for bugs, scaffolding boilerplate you already understand, writing docs.
  • Bad uses: pasting in an exercise and submitting the output, accepting code you can't explain, trusting API names and versions without checking the docs.

Debugging in the editor

Set breakpoints by clicking the gutter, press F5, and step through with F10/F11. Debugging beats console.log for anything non-trivial.

The rest of your toolbox

Browsers and DevTools

  • Chrome for development (best DevTools, Lighthouse, Performance panel); test also in Firefox (excellent CSS Grid/Flexbox inspectors, accessibility tools) and Safari (essential for iOS behavior).
  • Extensions: React Developer Tools, axe DevTools (accessibility), Lighthouse, Wappalyzer (what a site uses), Spector.js (WebGL frame capture), a JSON viewer, and ColorZilla or the built-in eyedropper.
  • Learn DevTools panels: Elements, Console, Sources (breakpoints), Network (throttling), Performance, Memory, Application (storage, service workers), Lighthouse, Rendering (paint flashing, FPS meter).

Terminal

  • macOS: iTerm2, Ghostty, Warp or the built-in Terminal. Use zsh with Oh My Zsh or Starship prompt, plus fzf (fuzzy find), ripgrep (rg, fast search), bat, eza, zoxide (smart cd), and tmux for sessions.
  • Windows: Windows Terminal with WSL2 (Ubuntu) so you develop in a Linux environment like production.
  • Package manager: Homebrew (macOS). Node versions: fnm, nvm or Volta. Package managers: npm (default), pnpm (fast, disk-efficient; great for monorepos).

Version control and collaboration

  • Git + GitHub CLI (gh) for pull requests from the terminal. A GUI such as GitHub Desktop, Fork, or Lazygit helps when visualizing branches.

Design and assets

  • Figma for UI design and reading designs. Excalidraw for quick diagrams.
  • Blender (free) for 3D modeling, baking and glTF export (“The 3D asset pipeline: Blender to web”). Poly Haven and ambientCG for free PBR textures and HDRIs. gltf.report and gltf-transform for model optimization.
  • Squoosh or sharp for image compression; SVGOMG for SVG optimization.

API, database and infrastructure tools

  • Bruno, Postman, Insomnia or Thunder Client to test APIs; curl and httpie in the terminal.
  • TablePlus, DBeaver or Drizzle Studio/Prisma Studio to inspect databases.
  • Docker Desktop or OrbStack (macOS) for containers (“CI/CD, Docker, cloud & edge deployment”).

Learning and reference

  • MDN Web Docs, javascript.info, react.dev, web.dev, threejs.org/docs and /examples, caniuse.com, bundlephobia, Shadertoy, The Book of Shaders.

Project-level configuration to copy

How to choose and stick with it

  1. Pick VS Code (or Cursor) for the whole course.
  2. Install the essentials above and the settings. Do not install 40 extensions on day one; add one when you feel a specific pain.
  3. Learn 10 shortcuts this week and 10 more next week.
  4. Use the debugger and the formatter on save every day.
  5. After Part 8, if you want to explore, try WebStorm or Zed for a week on a real project, then decide. Switching for a reason is fine; switching for novelty is a time sink.

Setup tasks

  1. Install your editor, the essential extensions and the settings above. Open a project and confirm format-on-save works.
  2. Create .prettierrc and an ESLint config in a Vite project and make the editor show lint errors inline.
  3. Set a breakpoint in a small Node script and step through it with the debugger.
  4. Install gh, authenticate, and create a repository from the terminal.
  5. Learn and use 10 shortcuts from the table for a full day; keep a note of which ones stuck.
