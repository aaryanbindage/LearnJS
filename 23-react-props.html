Lesson 23 — Components & props

Build UIs by composing small components and passing data between them.

Props

Props are the inputs to a component, passed like HTML attributes and received as one object. Props are read-only: a component must never modify its props.

Try it: add a Badge component, pass a shape prop to Avatar, and nest another Card inside a Card.

Thinking in components

  1. Draw boxes around the UI; each box with a single responsibility is a candidate component.
  2. Name by what it is (ProductCard), not where it's used.
  3. Put components in files: src/components/ProductCard.jsx with one default or named export.
  4. Pass the data the component needs, not a whole giant object it only uses one field of.
  5. Don't define components inside other components (they'd be recreated and lose state each render).
RuleNever mutate props: props.items.push(x) is a bug. Copy first. Components must be pure with respect to their props and state: same inputs → same output.
