Lesson 43 — Container queries, anchor positioning & view transitions

CSS now does things that once required JavaScript. This lesson covers the features that matter most. Support varies; always check caniuse.com and use @supports for progressive enhancement.

Container queries

Media queries respond to the viewport. Container queries respond to the size of the component's parent, so one component works in a sidebar and in a main column without knowing where it lives. This is what truly reusable components need.

Style queries (@container style(--theme: dark)) and container-type: size exist too. Note: an element can't query itself, only an ancestor container.

View Transitions

Animate between two DOM states (or two pages) with a browser-generated cross-fade or shared-element morph. In a single page, wrap the change in document.startViewTransition().

For multi-page sites: @view-transition { navigation: auto; } opts same-origin navigations into transitions, and matching view-transition-name values morph elements across pages. In SPAs the router (React Router's viewTransition prop, Next.js experimental flag) wires it up.

Anchor positioning (progressive)

Position a tooltip, popover or dropdown relative to another element in pure CSS, with automatic flipping when there's no room. This replaces Popper/Floating UI for simple cases. Combine with the Popover API for zero-JS accessible popovers. Support is newer, so wrap in @supports.

The Popover API (popover, popovertarget) gives light-dismiss, top-layer rendering and Escape handling for free. The <dialog> element does the same for modals (showModal()).

More platform features worth knowing

  • Nesting, @layer, color-mix(), oklch(), relative color syntax (oklch(from var(--brand) calc(l + .1) c h)).
  • text-wrap: balance | pretty, field-sizing: content (auto-growing textarea), interpolate-size (animate to height: auto), @starting-style (animate elements entering the DOM), transition-behavior: allow-discrete (animate display).
  • subgrid, scrollbar-gutter, overscroll-behavior, content-visibility: auto (skip rendering offscreen sections: big performance win).

Exercises

  1. Build a ProductCard that switches from stacked to horizontal by container width, and drop it into a narrow sidebar and a wide grid.
  2. Use :has() to build a CSS-only "filter chips" UI with checkboxes that hide non-matching cards.
  3. Add a view transition between a list item thumbnail and its detail image (shared view-transition-name set per item).
  4. Build a tooltip with the Popover API + anchor positioning with a JavaScript-free fallback.
  5. Create a scroll-linked reading progress bar and sections that reveal on scroll, with prefers-reduced-motion handling.
  6. Use content-visibility: auto on a long page and measure the rendering time change in the Performance panel.

Checkpoint

When container queries over media queries?When a component appears in different-width contexts. Media queries describe the page; container queries describe the component's available space.
How do you use new CSS safely?Treat it as progressive enhancement: the page must work without it. Wrap with @supports or feature-detect in JS, and test in Safari and Firefox.
