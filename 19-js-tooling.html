Lesson 19 — Errors, debugging, storage & tooling

Real programs fail. Learn to handle errors, find bugs fast, persist data, and use the Node/npm ecosystem.

Errors

Common types: TypeError (undefined is not a function, reading property of undefined), ReferenceError, SyntaxError, RangeError. Global nets: window.onerror and unhandledrejection for logging.

Debugging like a professional

  1. Read the error and the stack trace: first line = what, first stack frame in your code = where.
  2. console beyond log: console.table(array), console.dir(obj), console.group, console.time, console.assert, console.trace.
  3. debugger; / breakpoints: Sources panel → click a line number. Inspect scope variables, watch expressions, step over (F10), step into (F11), call stack.
  4. Conditional breakpoints and logpoints (right-click a line number).
  5. Network panel for API bugs: status, request payload, response.
  6. Binary search the bug: disable half the code. Make the smallest reproduction.
  7. Ask: "what did I assume that isn't true?" Then print the assumption.

Node & npm

  • package.json: metadata, dependencies, scripts. package-lock.json: exact versions (commit it). node_modules: never commit (add to .gitignore).
  • Semver: ^1.2.3 accepts minor/patch updates; ~1.2.3 only patches.
  • Vite gives a dev server with instant reload and an optimized production build. Quick start: npm create vite@latest myapp -- --template vanilla.
  • ESLint finds bugs; Prettier formats code. Run both in your editor.
  • Be careful with dependencies: fewer is safer. Check npm audit.
