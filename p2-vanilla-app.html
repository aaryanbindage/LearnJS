Project 2 — Weather & todo dashboard (vanilla JS)

Build a small dashboard with no frameworks. This project proves you understand the DOM, events, async, modules and storage, which is exactly what React will later abstract for you.

Requirements

Todo panel

  1. Add, complete-toggle, edit-in-place and delete todos. One delegated listener.
  2. Filter: All / Active / Done, with counts. Persist to localStorage.
  3. Keyboard accessible; announce changes via an aria-live region.

Weather panel

  1. Search a city; fetch coordinates from Open-Meteo's geocoding API, then the forecast. No API key needed.
  2. Show loading, error and empty states. Cancel stale requests with AbortController.
  3. Remember the last city; debounce the search input.

Engineering

  1. Vite + ES modules: api.js, store.js, ui.js, main.js. Pure logic in testable functions.
  2. At least 8 Vitest tests (filtering, store updates, API response mapping with a mocked fetch).
  3. Responsive and dark-mode aware using your CSS from Part 2.

Suggested architecture

Key ideaKeep a single state object, change it only through functions, and call one render(state) after each change. This "state → UI" loop is precisely what React automates in Part 4.

Stretch goals

  • Drag-and-drop reorder with the pointer events API.
  • 7-day forecast chart on a <canvas> (draw it yourself).
  • Installable PWA: manifest + service worker for offline todos.
  • Undo/redo using a history stack of immutable states.

Self-review checklist

Ready for Part 4 if…
  • No innerHTML with user data.
  • Every async path has loading and error UI.
  • Rapid typing never shows stale results.
  • Tests pass and cover logic that isn't DOM-related.
  • You can explain every line of the code.
