Lesson 66 — Advanced shaders & post-processing

Shaders run on the GPU, in parallel for every vertex and pixel. Mastering them unlocks effects no built-in material can do: water, force fields, dissolves, toon rendering, GPU particles and screen-space effects.

Pipeline recap

  1. Vertex shader runs per vertex: outputs gl_Position (clip space). Great for displacement, waves, wind, skinning.
  2. GPU rasterizes triangles and interpolates outputs (varyings) across each face.
  3. Fragment shader runs per pixel: outputs a color. Great for lighting, texturing, patterns, effects.

Uniforms are constants per draw call (time, resolution, colors, textures). Attributes are per-vertex data (position, uv, normal). Think in normalized coordinates and math functions: mix, smoothstep, step, fract, sin, length, dot, pow.

Extending built-in materials (keep lighting, add your effect)

Writing a full lighting model yourself is a lot of work. Instead, patch the built-in shader with onBeforeCompile (or use drei's shaderMaterial / three-custom-shader-material).

Techniques

EffectIdea
DissolveSample noise; discard where noise < threshold; add an emissive edge where noise ≈ threshold
Toon / cel shadingQuantize dot(normal, light) with step/gradient texture; add outlines with inverted-hull or post-process
WaterSum of sines or noise for waves; normal maps scrolling; fresnel blend of reflection/refraction; depth-based foam
Triplanar mappingTexture by world position along 3 axes: no UV stretching on terrain/cliffs
GPU particlesStore state in textures; update with a ping-pong render target (GPUComputationRenderer) or compute shaders (Lesson 67)
Raymarching / SDFRender implicit shapes in a fragment shader by marching rays through a distance function: metaballs, fractals, soft blends
Vertex animation texturesBake complex animation/simulation into textures; play on the GPU (crowds, cloth)

Post-processing

Render the scene to a texture, then run full-screen passes over it: bloom, depth of field, SSAO, color grading, vignette, chromatic aberration, outlines. Each pass costs fill-rate, so budget carefully on mobile.

Custom full-screen effect: write a fragment shader that samples tDiffuse (the rendered scene) at vUv and returns a modified color (e.g., pixelate by snapping UVs, or RGB split by offsetting each channel).

Debugging shaders

  • Output intermediate values as colors: gl_FragColor = vec4(vec3(value), 1.0), normal * 0.5 + 0.5, vec3(vUv, 0.0).
  • GLSL is strict: 1 vs 1.0, matching vector sizes, no implicit conversions. Read the compile log in the console.
  • Tools: Spector.js (capture GL calls), Shadertoy (prototype fragment shaders), The Book of Shaders (learn), Chrome's Performance panel and GPU profiling, renderer.info.
  • Performance: avoid branching on divergent conditions, minimize texture reads and pow/sin in hot loops, lower precision on mobile (mediump where safe), don't overdraw large transparent layers.

Exercises

  1. Work through The Book of Shaders chapters 1–11; port three of your Shadertoy experiments to a Three.js ShaderMaterial.
  2. Implement a dissolve effect on a glTF model by patching MeshStandardMaterial with onBeforeCompile, driven by a uniform slider.
  3. Write a stylized water plane: animated normals, fresnel, depth fade using the depth texture, foam at the shoreline.
  4. Build a toon material with a 3-step gradient and an inverted-hull outline.
  5. Add bloom, vignette and a custom chromatic-aberration pass; expose controls with lil-gui; measure the frame-time cost of each pass.
  6. Raymarch a scene of three metaballs in a full-screen quad and shade it with normals from the SDF gradient.

Checkpoint

Where does a varying get its value in the fragment shader?The GPU interpolates the vertex shader outputs across the triangle's surface, so each pixel receives a blended value for its position.
Why use onBeforeCompile instead of a new ShaderMaterial?It keeps Three's lighting, shadows, fog and tone-mapping code, so you add one effect without rewriting the whole PBR shader.
