Lesson 36 — Shaders (GLSL)

Shaders are tiny programs that run on the GPU, in parallel, for every vertex and every pixel. They are the source of most "wow" effects on the web.

The GPU pipeline

  1. Vertex shader: runs once per vertex. Its job: output the vertex's final screen position (gl_Position). You can also move vertices here (waves, wind, morphing).
  2. The GPU turns triangles into pixels (rasterization) and interpolates values (varyings) between vertices.
  3. Fragment shader: runs once per pixel covered. Its job: output a color (gl_FragColor / an out variable).

Exercises

  1. Make the fragment shader output vec4(vUv, 0.0, 1.0) and confirm you understand each corner's color.
  2. Draw a circle in the fragment shader using length(vUv - 0.5) and smoothstep; animate its radius with time.
  3. Build a fresnel rim-light: pow(1.0 - dot(normalize(vNormal), normalize(vViewDir)), 3.0) added to the color.
  4. Build a dissolve effect with noise and a uProgress uniform you control with a lil-gui slider (use discard).
  5. Make a sphere "breathe" by displacing vertices along their normals with time.
  6. Port one Shadertoy shader into the full-screen template above.

Checkpoint

Uniform vs varying?A uniform is one value shared by every vertex and pixel in a draw call (set from JS). A varying is computed per vertex and interpolated to each pixel.
Why can't I write float x = 1; in GLSL ES?GLSL is strictly typed: an integer literal can't initialize a float. Write 1.0.
