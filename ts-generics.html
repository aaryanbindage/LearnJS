Generics & utility types

You've been using generics for a while: Promise<number>, Map<string, number>, querySelector<HTMLInputElement>. In this TypeScript lesson you'll learn what those angle brackets mean, write your own generic functions and types, and use TypeScript's built-in "utility types" to build new types from existing ones.

Generic functions

The <T> after the function name declares a type parameter: a placeholder for a type, filled in each time the function is called. Read the signature as: "for any type T, first takes an array of T and returns a T (or undefined)".

AnalogyA normal parameter is a blank for a value: double(n) works for any number. A type parameter is a blank for a type: first<T> works for any type. When you call first([1, 2, 3]), TypeScript looks at the argument and fills in T = number.

T is just a name (short for "type"); you could call it Item. Single capital letters are the convention: T, then U, or K and V for keys and values.

Usually TypeScript works out T from the arguments. You can also fill it in yourself, in angle brackets at the call. That's what you did with querySelector<HTMLInputElement> and new Map<string, number>():

Generic types

Types can have type parameters too. A very common real-world example: every response from your server has the same wrapper, but different data inside.

Utility types: building types from types

TypeScript has built-in generic types that transform other types. They save you from writing near-duplicate types by hand. Hover over each one:

UtilityGives you
Partial<T>T with every property optional (good for "updates")
Required<T>T with every property required
Pick<T, Keys>only the listed properties
Omit<T, Keys>everything except the listed properties
Readonly<T>T where no property can be reassigned
Record<K, V>an object with keys K and values V
ReturnType<typeof fn>whatever a function returns
Awaited<P>what a promise resolves to

Common mistakes
  • Generics where none are needed: if T appears only once in the signature, you probably don't need it. Generics are for connecting types (input to output).
  • Using any instead of a generic: you lose all checking on the result.
  • Forgetting a constraint when you use a property of T: add T extends { ... }.
  • Copy-pasting near-identical types: derive them with Pick, Omit, Partial.

Recap

  • A type parameter (<T>) is a placeholder for a type, usually inferred from the arguments.
  • Generic functions connect input and output types: first<T>(items: T[]): T | undefined.
  • Generic types: type ApiResponse<T> = .... Array, Promise, Map, Record are all generic.
  • T extends X constrains T; keyof T is the union of T's keys; T[K] is the type of key K.
  • Utility types: Partial, Required, Pick, Omit, Readonly, Record. typeof value turns a value into a type.
