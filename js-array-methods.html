Array methods: map, filter, find & reduce

In the arrays lesson you wrote loops to transform lists, keep some items, and add things up. Those jobs are so common that arrays have built-in methods for each one. You hand them a callback (remember those?) and they do the looping for you.

In this lesson you will

  • Transform every item with map.
  • Keep only matching items with filter.
  • Find one item with find, and test items with some and every.
  • Combine everything into one value with reduce.
  • Sort arrays correctly, and chain methods together.
  • See how TypeScript follows the types through every step.

About 55 minutes. Make sure you're comfortable with arrow functions and callbacks first.

AnalogyThink of a factory conveyor belt. Each item on the belt goes past a machine. map is a machine that changes each item. filter is a machine that lets some items through and drops others. reduce is the box at the end that collects everything into one result.

map: transform every item

map makes a new array, the same length, where each item is whatever your callback returned for the original item.

filter: keep some items

filter makes a new array containing only the items where your callback returns true. The callback is a yes/no question asked of each item.

A neat trick: to remove an item from a list without changing the original, keep everything that isn't it:

What does [1, 2, 3, 4, 5, 6].filter((n) => n % 2 === 0) give?

It keeps the numbers whose remainder when divided by 2 is 0, which are the even numbers. (The third answer is what map with the same callback would give!)

TipAlways give reduce a starting value (the second argument). And if a reduce gets hard to read, a plain for...of loop is perfectly fine. Clear code beats clever code.

Sorting

sort puts an array in order, but it has two surprises. First, by default it sorts everything as text, which gives odd results for numbers:

As text, "100" comes before "9" because "1" comes before "9", like in a dictionary. To sort numbers, give sort a compare function. (a, b) => a - b sorts smallest first; (a, b) => b - a sorts biggest first:

The second surprise: sort changes the original array (unlike map and filter). That's why the examples copy first with [...nums]. Newer browsers also have toSorted(), which returns a sorted copy.

Chaining methods

Since map and filter return arrays, you can call another method straight on the result. Put each step on its own line and it reads like a recipe:

Which method do I need?

I want to…UseGives back
change every itemmapnew array, same length
keep some itemsfilternew array, same or shorter
get the first matchfindone item, or undefined
ask "any?" / "all?"some / everytrue or false
combine into one valuereduceanything (a number, string, object…)
just do something with each itemfor...of (or forEach)nothing
Common mistakes
  • Forgetting to return in a braces callback: arr.map((x) => { x * 2 }) gives [undefined, undefined, …].
  • Using map to filter: map always returns the same number of items.
  • Expecting find to return an array: it returns one item (or undefined). Use filter for all matches.
  • Sorting numbers without a compare function.
  • Forgetting reduce's starting value.

Recap

  • map transforms each item; filter keeps matching items. Both return new arrays and leave the original alone.
  • find returns the first match or undefined. some/every return booleans.
  • reduce((acc, item) => newAcc, start) combines everything into one value. Always pass a start value.
  • Sort numbers with sort((a, b) => a - b). sort changes the original, so copy first.
  • Chain methods, one step per line.
  • TypeScript infers callback parameter types, tracks how map changes types, and makes you handle find's possible undefined.
