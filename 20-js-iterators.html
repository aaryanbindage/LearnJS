Map, Set, iterators & generators

Arrays and objects cover most needs, but JavaScript has two more built-in collections that are better at certain jobs: Set for unique values and Map for lookups. You'll also see what makes for...of work, and get a first taste of regular expressions for searching text.

In this lesson you will

  • Remove duplicates and test membership quickly with Set.
  • Store key/value pairs with Map, and know when to prefer it over a plain object.
  • Understand iterables, and write a simple generator function.
  • Match patterns in text with basic regular expressions.
  • Type all of these in TypeScript.

About 45 minutes.

Set: a collection of unique values

A Set is like an array that can't contain the same value twice. Adding something that's already there does nothing.

The most common use is removing duplicates from an array: make a Set from it, then spread it back into an array.

set.has(x) is also much faster than array.includes(x) for big collections, because a Set doesn't have to look through every item. Loop over a Set with for...of, just like an array.

Try itGiven two arrays of names, use a Set to find the names that appear in both. (Hint: make a Set from one array, then filter the other with set.has.)

Map: key/value pairs

A Map stores pairs of keys and values, like the "dictionary" objects you made in the objects lesson, but designed for the job:

Why use a Map instead of an object?

  • Keys can be anything, not just strings: numbers, objects, even DOM elements.
  • It has a size, and it's designed for adding and removing entries often.
  • There's no risk of clashing with built-in object properties (an object already "has" keys like toString).
Rule of thumbFor a fixed "record" with known fields (a user, a product), use an object. For a lookup table that grows and shrinks, or when keys aren't strings, use a Map.

Generators: making your own sequences

A generator function (written function*) produces values one at a time with yield. Each time the loop asks for the next value, the function runs until the next yield, hands over that value, and pauses.

Regular expressions: patterns in text

A regular expression (regex) is a mini-language for describing patterns in text, like "a word that starts with a capital letter" or "digits followed by px". It's written between slashes:

PatternMatches
\da digit 0–9
\wa letter, digit or underscore
\swhitespace (space, tab, new line)
.any character
+, *, ?one or more, zero or more, optional (of the thing before)
{3}exactly 3 of the thing before
[abc]any one of a, b, c
^, $start, end of the text
/g, /iflags: find all matches; ignore case
TipRegex is powerful but hard to read. Keep patterns simple, add a comment explaining each one, and test them on a site like regex101.com. For anything complex (like fully validating an email address), use a library or the browser's built-in validation instead.

Recap

  • new Set() holds unique values: add, has, delete, size. [...new Set(arr)] removes duplicates.
  • new Map() holds key/value pairs with any type of key: set, get, has, delete, size.
  • Strings, arrays, Sets and Maps are iterable: they work with for...of and spread. Plain objects aren't.
  • function* generators yield values one at a time.
  • Regex: /pattern/flags, with test, match, replace, split.
  • TypeScript: Set<T>, Map<K, V>; map.get and match might return nothing.
