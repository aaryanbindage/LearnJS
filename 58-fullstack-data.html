Connect the database to your UI safely and ergonomically: typed queries, mutations from forms, cache invalidation and uploads.

ORMs remove boilerplate and give types, but they can generate poor queries. Learn SQL first (“Databases & SQL”) and inspect the SQL your ORM emits.

Server Actions: mutations without writing an API

A Server Action is an async function marked "use server" that you can call from forms and client components. Under the hood it's an HTTP POST endpoint, so treat it as a public API: authenticate, authorize and validate inside every action.

This form works before JavaScript loads (progressive enhancement), because it's a real <form>. Optimistic UI: useOptimistic shows the expected result instantly and reconciles when the server responds.

Files and uploads

  1. Server creates a presigned upload URL (S3, Cloudflare R2, Supabase Storage, UploadThing) after checking auth and file type/size limits.
  2. Browser uploads directly to object storage (the file never passes through your server).
  3. Client tells your server the final object key; server saves metadata in the DB and queues post-processing (resize, virus scan).
  4. Serve through a CDN with image transformation; keep private files behind signed URLs.

Data integrity patterns

  • Optimistic concurrency: add a version column; UPDATE … WHERE id=$1 AND version=$2; if 0 rows updated, someone else changed it (return 409).
  • Soft deletes, audit trails, outbox pattern (write an event row in the same transaction, a worker publishes it) for reliable side effects.
  • Seed and test data: factories, a seed script, ephemeral test databases (Docker, Testcontainers).
  • Backups and migrations: automated backups with tested restores; backwards-compatible migrations (add column → deploy code → backfill → enforce → drop old).

Exercises

  1. Model a blog (users, posts, comments, tags) in Prisma or Drizzle, run migrations, seed data, and inspect the generated SQL for a nested query.
  2. Build create/edit/delete post pages with Server Actions, Zod validation, field errors, useActionState, pending UI and revalidatePath.
  3. Add optimistic UI for likes with useOptimistic; make the server action fail intermittently and handle rollback.
  4. Implement cache-aside with Redis/Upstash for a hot query; measure latency before and after; implement safe invalidation.
  5. Implement presigned uploads to R2/S3 with size/type limits and an image resize job.
  6. Implement optimistic concurrency control with a version column and show a conflict UI.

Checkpoint

Why validate inside a Server Action even though the form validates?Server Actions are public HTTP endpoints; anyone can call them directly with arbitrary data, so server-side validation and authorization are mandatory.
What is an N+1 query and how does an ORM help or hurt?One query for a list plus one per item. ORMs can make it easy to trigger accidentally by lazy-loading; use eager loading/includes or joins to fetch relations in a single query.
