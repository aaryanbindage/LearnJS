Project 3 — A full React app

Build a real product with routing, server data, global state, forms, tests and a deployment. Pick one idea below (or propose your own of similar scope).

Pick a project

  • Movie/Book explorer: search a public API (TMDB, Open Library), details page, favorites list, filters in the URL.
  • Kanban board: drag cards between columns, persist to localStorage (or a small backend), undo/redo via a reducer.
  • Budget tracker: transactions, categories, charts, monthly summaries, CSV export.
  • Recipe app: search, scale ingredient quantities, shopping list that merges duplicate items.

Requirements

  1. Stack: Vite + React (TypeScript encouraged) + React Router + TanStack Query. Zustand or Context+reducer for client state.
  2. Screens: at least 4 routes, including a dynamic :id route, 404 page and an error boundary.
  3. Data: loading, error, empty, and success states for every request; request cancellation; optimistic update for at least one mutation.
  4. Forms: one non-trivial form with validation (React Hook Form + Zod, or hand-rolled), accessible error messages.
  5. State in the URL: search term, filters and page are shareable links.
  6. Accessibility: keyboard-operable everywhere, focus management on route change and modals, Lighthouse a11y ≥ 95.
  7. Performance: route-level code splitting; images lazy-loaded; no needless re-render hot spots (verified in Profiler).
  8. Testing: at least 10 Testing Library tests (reducer/store logic, form validation, one async data flow with mocked network). One Playwright smoke test.
  9. Quality: ESLint (with hooks plugin) + Prettier clean; meaningful commit history; README with screenshots.
  10. Deployment: public URL on Netlify/Vercel/Cloudflare, deep links work.

Milestones

  1. Day 1: Plan screens (sketch), data model, folder structure. Scaffold, routing skeleton, layout.
  2. Day 2: Data layer (API client + queries). List and detail pages with all four states.
  3. Day 3: Client state (favorites/cart/board), persistence, forms.
  4. Day 4: Accessibility pass, performance pass, responsive polish and dark mode.
  5. Day 5: Tests, CI (GitHub Actions running lint + tests + build), deploy, README.

Starter checklist

Self-review

Questions a reviewer would ask you
  • Where does each piece of state live and why there?
  • What happens when the network is slow, offline or returns an error?
  • Is any state derived data that you stored? Any effect that should be an event handler?
  • Can I complete every task using only a keyboard?
  • What would break if I deleted the useMemos?
