Lesson 8 — Positioning, responsive design & variables

Place elements precisely, make layouts adapt to any screen, and use custom properties to build themeable systems.

Positioning

ValueBehavior
staticDefault, normal flow
relativeNormal flow, offset from its own spot; becomes an anchor for absolute children
absoluteRemoved from flow; positioned against the nearest positioned ancestor
fixedPositioned against the viewport
stickyNormal flow until a scroll threshold, then sticks
  • z-index only works on positioned elements (and flex/grid items). It operates inside stacking contexts (created by position + z-index, opacity < 1, transform, etc.).
  • inset: 0 is shorthand for top/right/bottom/left 0.

Responsive design

Three ingredients: a viewport meta tag, flexible layout (flex/grid/%), and media queries where flexibility isn't enough.

Mobile-first: write base styles for small screens, then add complexity at larger widths with min-width queries.

Modern responsive tools

Don't target specific devices. Add a breakpoint where your content starts to look bad (drag the DevTools device toolbar slowly).

Custom properties (CSS variables)

Define with --name, read with var(--name, fallback). They cascade and inherit, and can change at runtime, which makes theming trivial.

Tip: keep a small design-token set (colors, spacing, radius, font sizes) in :root and use only those throughout.

Exercises

  1. Build a card with a badge pinned to its top-right corner using relative + absolute.
  2. Make a sticky table header and a sticky sidebar.
  3. Take your Lesson 7 dashboard and make it mobile-first with two breakpoints.
  4. Create light, dark and "high-contrast" themes using only custom properties and a data-theme attribute.
  5. Use a container query so a card switches from stacked to side-by-side based on its own width.
  6. Test with DevTools device mode and a real phone on your local network.

Checkpoint

Why is my absolutely positioned child in the wrong place?No ancestor is positioned, so it uses the viewport/initial containing block. Add position: relative to the intended parent.
Why mobile-first?Small-screen styles are simpler, so the base is lean and enhancements load only where needed; min-width queries layer cleanly.
