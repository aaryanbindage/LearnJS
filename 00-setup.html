Start here: how the web works

Welcome! This course takes you from never having written code to building real web apps in JavaScript and TypeScript, and beyond. You don't need any experience. This first lesson explains how the course works, what the web is made of, and how to set up your computer.

In this lesson you will

  • Learn how to use this course, and its live code editors.
  • Understand, in plain English, what happens when you visit a website.
  • Meet the languages you'll learn: HTML, CSS, JavaScript and TypeScript.
  • Install the free tools professionals use.

How this course works

  • Go in order. Each lesson builds on the ones before it. Use the list on the left (or the ☰ Lessons button on a phone) to move around. Your progress is saved in your browser.

What happens when you visit a website?

Let's follow what happens when you type example.com into your browser and press Enter.

  1. Finding the computer. Websites live on computers called servers, which are always connected to the internet. Every computer online has a number address (an IP address, like 93.184.215.14). Your browser asks the internet's phone book, called DNS, "what's the number for example.com?"
  2. Asking for the page. Your browser sends a message to that server: "please send me your home page". This message is an HTTP request. (The https at the start of web addresses means the conversation is encrypted, so nobody in between can read it.)
  3. Getting the page. The server sends back an HTTP response: usually an HTML file. The response also has a status code: 200 means OK, and you've probably seen 404, which means "not found".
  4. Drawing the page. The browser reads the HTML, notices it also needs some CSS, JavaScript and images, asks the server for those too, and then draws (renders) everything on your screen.
AnalogyIt's like ordering from a restaurant by phone. You look up the number (DNS), call and place your order (request), the kitchen sends back your food (response), and you arrange it on your table (rendering).

The languages of the web

A web page is made with three languages, each with its own job. You'll learn them in this order:

LanguageIts jobAnalogy: a house
HTMLThe content and structure: headings, paragraphs, images, buttons.The walls and rooms
CSSHow it looks: colours, fonts, layout, animation.The paint and furniture
JavaScriptHow it behaves: reacting to clicks, loading data, games, apps.The electricity and plumbing
TypeScriptJavaScript with extra safety checks that catch mistakes before your code runs. Most professional JavaScript is written in it.A building inspector who checks the wiring before you switch it on

HTML and CSS aren't programming languages: they describe things rather than giving step-by-step instructions, which makes them a gentle place to start. JavaScript and TypeScript are where you'll learn to program, starting in Part 3. Later parts cover React (for building big apps), Three.js (3D graphics), servers and databases.

Install your tools

You can do Parts 1 to 3 entirely in this website's editors. But you'll want real tools soon, and installing them now means they're ready. Everything here is free.

  1. A modern browser: Chrome, Edge or Firefox. You probably have one.
  2. A code editor: the program you'll write code in. This course gives instructions for two free, excellent ones. Either is a great choice; pick one and stick with it.

    VS Code, from code.visualstudio.com. It's the most widely used editor, with a huge library of add-ons. Install it, open it, then click the Extensions icon (four squares) on the left and install:

    • Live Server (shows your HTML in the browser, and refreshes it every time you save)
    • Prettier (tidies up your code's formatting)
    • ESLint (warns you about likely mistakes)

    Zed, from zed.dev (for Mac, Windows and Linux). It's very fast, and comes with what you need already built in: TypeScript support, automatic formatting with Prettier, and a terminal. There's nothing extra to install to get started. (When you first open an HTML file, Zed may offer to install its HTML extension: say yes.)

  3. Node.js, from nodejs.org. Choose the "LTS" version (that means "long-term support", the stable one). It runs JavaScript outside the browser, and installs tools you'll use in Part 4.
  4. Git, from git-scm.com. It saves the history of your projects, so you can always go back.

Your browser's developer tools

Every browser has hidden tools for web developers, called DevTools. Open them on any page with F12 (or Cmd + Option + I on a Mac). Have a look around for a few minutes; you'll use them a lot:

  • Elements: the page's HTML and CSS. You can edit anything here to experiment. Changes disappear when you reload, so you can't break the real site.
  • Console: where JavaScript messages and errors appear. You'll use this from Part 3.
  • Network: every file the page loaded. Reload the page with this tab open and watch the requests appear, each with its status code.
Try it
  1. Open any website you like, and open DevTools.
  2. In the Elements tab, click the arrow icon at the top-left of DevTools, then click a heading on the page. Its HTML is highlighted.
  3. Double-click the heading's text in the Elements panel and change it. You've just "edited" a famous website (only on your screen).

Check your understanding

What's the difference between a request and a response?The request is your browser asking a server for something. The response is the server's reply, usually with the file you asked for and a status code.
Which language would you use to make a button change colour when clicked?CSS defines the colours, and JavaScript reacts to the click and switches between them. The button itself is HTML. Real pages use all three together.
What does a 404 status code mean?"Not found": the server doesn't have anything at that address.
