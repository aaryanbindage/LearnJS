Async code: promises, fetch & await

Some things take time: loading data from a server, waiting for a timer, reading a file. JavaScript doesn't freeze while it waits. Instead, it carries on and comes back when the result is ready. This lesson explains how that works and how to write it clearly with async and await.

In this lesson you will

  • Understand the difference between synchronous and asynchronous code.
  • Know what a Promise is.
  • Write asynchronous code that reads top-to-bottom with async/await.
  • Load real data from the internet with fetch, and handle errors.
  • Run several requests at once with Promise.all.
  • Type promises and fetched data in TypeScript.

Waiting without freezing

Everything you've written so far has been synchronous: each line finishes before the next one starts. That's fine for math, but imagine loading data from a server on the other side of the world, which might take a second or two. If JavaScript stopped and waited, the whole page would freeze: no scrolling, no clicking, nothing.

So slow operations are asynchronous: you start them, JavaScript carries on with other things, and your code is notified when the result arrives. You've already seen this with setTimeout:

The output order is 1, 2, 3, not the order of the lines. setTimeout starts the timer and returns immediately; its callback runs later.

AnalogyOrdering at a busy café. You order, they give you a buzzer, and you go and sit down. You don't stand at the counter blocking everyone. When your food is ready, the buzzer goes off and you collect it. The buzzer is a promise: "your result is coming".

Promises

A Promise is an object that represents a result that isn't ready yet. It's always in one of three states:

  • pending: still waiting (the buzzer hasn't gone off)
  • fulfilled: finished successfully, with a value (your food)
  • rejected: failed, with an error (they ran out of pizza)

async and await

Inside a function marked async, you can put await in front of a promise. await pauses that function until the promise is done, and gives you its result. The rest of the page keeps running in the meantime.

Look at makeBreakfast: it reads top to bottom, like normal code, even though it takes two seconds. That's the point of await. And the last line still prints immediately, because only makeBreakfast pauses, not the whole program.

Two rules:

  1. await can only be used inside an async function (or at the top level of a module, which is what the editors here are).
  2. An async function always returns a promise. Whatever you return becomes the promise's value.

There are two awaits, because there are two waits:

  1. await fetch(...) waits for the server to start replying. You get a Response object with the status code (200 means OK) and headers.
  2. await response.json() waits for the rest of the data to arrive, and converts it from JSON (a text format for data that looks just like JavaScript objects) into a real object.

When things go wrong

Network requests fail all the time: no internet, the server is down, the address is wrong. There are two kinds of failure:

  • The request couldn't be made at all (offline, bad domain). The fetch promise rejects, which throws an error at the await.
  • The server replied, but with an error status like 404 (not found) or 500 (server error). fetch does not treat this as a failure! You have to check response.ok yourself.

Handle both with try/catch. Code in try runs normally; if anything in it throws an error, JavaScript jumps straight to catch, instead of crashing:

(console.time and console.timeEnd measure how long the code between them takes.) "All at once" should take about half as long. If any promise in Promise.all fails, the whole thing fails. Use Promise.allSettled when you want every result, success or not.

How it works underneath: the event loop

JavaScript runs one thing at a time. While your code runs, nothing else can. Async callbacks wait in a queue, and the browser runs them one by one, whenever the current code has finished. This system is called the event loop. Its consequence for you:

Even a 0 ms timer waits until the current code finishes. That's why a long loop freezes the page: event handlers, timers and screen updates all wait in the queue until it's done.

Common mistakes
  • Forgetting await: const data = fetch(url) gives you a promise, not the data. You'll see Promise { … } or "undefined" properties.
  • Forgetting await res.json(): res.json() is also a promise.
  • Not checking res.ok: a 404 page doesn't throw.
  • Using await in a non-async function: a syntax error. Add async.
  • Using a value before it's loaded: code after an un-awaited call runs before the data arrives.

Recap

  • Slow operations are asynchronous: they start now and finish later, without freezing the page.
  • A Promise is a placeholder for a future value: pending, fulfilled or rejected.
  • async functions can await promises, which reads like normal top-to-bottom code. They always return a promise.
  • const data = await (await fetch(url)).json(). Check res.ok; wrap in try/catch.
  • Promise.all runs independent tasks at the same time.
  • TypeScript: Promise<T>, catches forgotten awaits. Type fetched data (and validate it if you don't trust it). catch (err) is unknown.

What does await do?It pauses the current async function until the promise settles, then gives you its value (or throws its error). Other code keeps running meanwhile.
Does fetch throw on a 404?No. It only rejects if the request couldn't be made. Check response.ok for HTTP errors.
