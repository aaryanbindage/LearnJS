Lesson 22 — Why React, Vite & JSX

React lets you describe what the UI should look like for the current data and handles updating the DOM for you.

The problem React solves

In Project 2 you kept a state object and wrote render(state) by hand, carefully updating the DOM. As apps grow, keeping the DOM and data in sync becomes the main source of bugs. React makes it declarative:

Core ideaUI = f(state). You write a function that returns what the screen should look like. When state changes, React calls it again, compares the result with the previous one (reconciliation), and makes the minimal DOM changes.
  • Components: reusable, self-contained pieces of UI.
  • One-way data flow: data goes down via props; events go up via callbacks.
  • Ecosystem: Next.js/Remix for full-stack, React Router, TanStack Query, React Three Fiber.

Your first component (live)

In these live demos, React hooks are pre-imported and your component must be named App. In real projects you write import { useState } from "react".

JSX rules

JSX is syntax sugar: <h1 className="x">Hi</h1> compiles to React.createElement("h1", { className: "x" }, "Hi"). It's JavaScript, not HTML.

  • Components are functions whose names start with a capital letter (<Card />); lowercase means a DOM tag.
  • Only expressions go inside {}. No if/for statements; use ternaries, &&, and map.
  • React escapes strings in {} automatically, which protects against XSS.
