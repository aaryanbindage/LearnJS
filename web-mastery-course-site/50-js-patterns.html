Lesson 50 — Design patterns in JavaScript

Patterns are named solutions to recurring problems. They give teams a shared vocabulary. In JavaScript, closures, first-class functions and modules replace much of the class ceremony from older languages.

Principles behind the patterns

  • Single responsibility: one reason to change per module.
  • Open/closed: extend behavior without editing core code (strategies, plugins).
  • Depend on abstractions: pass in what you need.
  • Composition over inheritance, immutability by default, make illegal states unrepresentable.
  • YAGNI: don't add a pattern until the problem exists. Three similar lines beat a premature abstraction.

Checkpoint

Why is a state machine better than several booleans?Booleans allow impossible combinations (loading and error at once). A machine enumerates legal states and transitions, so illegal ones can't occur.
What is dependency injection buying you?Testability and flexibility: collaborators are supplied from outside, so you can substitute fakes or alternative implementations without changing the code.
