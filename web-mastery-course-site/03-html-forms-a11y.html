Lesson 3 — Forms, tables & accessibility

Collect input, present tabular data, and make everything usable by everyone.

Forms

Try submitting this form empty, then with a bad email. The browser validates for free.

  • Every input needs a <label>, linked by for/id or by wrapping.
  • name is the key sent to the server; value is the data.
  • Input types: text email password number tel url date time color range file search checkbox radio hidden.
  • Validation attributes: required pattern minlength maxlength min max step. Style with :invalid and :valid.
  • method="get" puts data in the URL (searches); post sends it in the body (changes data).
  • A <button> inside a form submits by default. Use type="button" otherwise.

Tables (tabular data only, never layout)

colspan and rowspan merge cells.

Accessibility essentials

  1. Semantic HTML first. It gives keyboard and screen-reader support for free.
  2. Keyboard: everything reachable with Tab, activatable with Enter/Space, with a visible focus ring. Never outline: none without a replacement.
  3. Text alternatives: alt, captions, transcripts.
  4. Contrast: at least 4.5:1 for body text (WCAG AA).
  5. ARIA is a last resort. No ARIA beats bad ARIA. Useful: aria-label, aria-expanded, aria-live="polite", aria-hidden.
  6. Never convey information by color alone.
  7. Real <button> for actions, real <a> for navigation.
  8. Put a skip link first in the body: <a href="#main">Skip to content</a>.
Common mistakeA placeholder is not a label. It disappears while typing and often has poor contrast.

Exercises

  1. Build a registration form with 6+ input types, all labeled and validated. Use method="get" and read the URL after submitting.
  2. Build a table of 5 items with a caption, header scopes and a footer total.
  3. Operate your forms using only the keyboard.
  4. Run Lighthouse (DevTools) on your page and reach 100 for Accessibility.
  5. Turn on VoiceOver (Cmd+F5) and listen to your page.

Checkpoint

Why can't <div onclick> be a button?It isn't focusable, has no button role for assistive tech, and doesn't respond to Enter/Space. A real <button> provides all of that.
What's wrong with placeholder-as-label?It vanishes on input, has low contrast, and isn't reliably announced as a label.
