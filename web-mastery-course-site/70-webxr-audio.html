Lesson 70 — WebXR, spatial audio & cross-device 3D

Sound and immersion complete a 3D experience. Learn Web Audio for interactive sound, spatialize it in a 3D scene, and extend your scene to VR/AR headsets and phones with WebXR, while making everything work on every input type.

Web Audio basics (live)

Web Audio is a graph: sources → effect nodes (gain, filter, delay, panner, compressor) → destination. Browsers require a user gesture before audio can start (the "autoplay policy"), so create or resume the AudioContext inside a click handler.

  • Schedule with ctx.currentTime and AudioParam methods (setValueAtTime, linearRampToValueAtTime, setTargetAtTime). The audio clock is far more precise than setTimeout.
  • Play recorded sounds: fetch → decodeAudioData → AudioBufferSourceNode (one-shot per play; cheap). Use compressed formats (Opus/AAC/MP3) and sprite sheets for many short sounds.
  • Libraries: Howler.js (simple), Tone.js (music, sequencing, synths), Three.js PositionalAudio.
  • For heavy DSP use AudioWorklet (runs on the audio thread, like a Worker for sound).

WebXR: VR and AR in the browser

WebXR gives your page access to headsets (Quest, Vision Pro, PC VR) and phone AR (Android Chrome). The scene, camera and render loop are the same Three.js you know; the XR session drives the camera pose and provides controllers/hands.

VR design rules

  • Frame rate is comfort: sustain 72–120 fps; dropped frames cause motion sickness. Budget far tighter than desktop (Lesson 68): low poly counts, baked lighting, minimal transparency and post-processing, MSAA over screen-space AA.
  • Never move the camera without the user's input (no unexpected acceleration, camera shake, forced rotation). Use teleport or snap-turn, add vignettes for smooth locomotion.
  • Scale is real-world meters: a door is ~2 m. Test in the headset constantly; the emulator isn't enough.
  • UI: place panels 1–2 m away, large text, world-space (not head-locked). Use ray or direct poke interactions; support hands and controllers.
  • Develop with the Immersive Web Emulator (browser extension) and a real headset over HTTPS (ngrok/Cloudflare tunnel, or adb reverse for Quest).

Exercises

  1. Extend the synth: add an ADSR envelope, a delay effect with feedback, and a keyboard (A–K keys) playing notes. Add a visualizer.
  2. Build a 3D scene with a moving engine/drone using PositionalAudio; vary pitch with speed and volume with distance; add a mute button that persists.
  3. Load a drum-sample sprite sheet and make a clickable 3D drum pad with per-pad sounds scheduled precisely using the audio clock.
  4. Add VRButton to an existing scene; implement teleport locomotion with a controller ray and a floor target; test with the Immersive Web Emulator.
  5. Build an AR "place a model on the table" demo using hit-test (Android Chrome) and the ARButton.
  6. Create quality presets (low/medium/high) auto-selected by detect-gpu, with a manual override in settings; verify on a phone and a desktop.

Checkpoint

Why must audio start from a click?Browsers block autoplaying sound to protect users; an AudioContext starts suspended until a user gesture lets you call resume().
Why setAnimationLoop instead of requestAnimationFrame for XR?In XR the headset owns the frame timing and passes the pose with each frame callback; setAnimationLoop hooks into the XR session's loop, which requestAnimationFrame on the window cannot.
