Lesson 48 — Advanced types: generics, mapped, conditional

TypeScript's type system is a small programming language. Library authors use it to make APIs that infer everything. You need enough of it to read library types and to build a few of your own, without overdoing it.

When not to be clever

  • Type-level code is hard to read and slow to compile. If a type needs a comment longer than the function, simplify the design.
  • Hide complexity behind a simple public signature; keep the tricky part inside one well-tested utility.
  • Test types with expectTypeOf (Vitest) or tsd for library code.
  • Read the types of libraries you use (Cmd+click in your editor): the fastest way to learn.

Exercises

  1. Implement MyPick, MyOmit, MyReadonly, DeepPartial, Awaited and ReturnType without using the built-ins. Try the type-challenges repo on GitHub (easy and medium sets).
  2. Write Paths<T>: all dot-notation key paths of a nested object ("a" | "a.b" | "a.b.c"), then get(obj, "a.b") typed to return the right value type.
  3. Build the typed Emitter above and extend it with once and off.
  4. Create branded Email and UserId types with validated constructors.
  5. Write a typed createStore(initialState, reducers) where action creators are inferred from reducer names.
  6. Read the type definitions of @tanstack/react-query's useQuery and explain how it infers the data type from queryFn.

What does infer do?Inside a conditional type it declares a type variable the compiler fills in with whatever part of the matched type is in that position.
Why use branded types?TypeScript is structural, so two ids that are both numbers are interchangeable. Brands add a phantom property that makes them distinct at compile time.
