Lesson 65 — Procedural generation & custom geometry

Instead of authoring every vertex, you write code that generates worlds: terrain, planets, trees, cities, particles. This lesson covers building BufferGeometry by hand, noise, and instancing, with a live terrain demo.

BufferGeometry from scratch

All Three.js geometry is typed arrays: position (x,y,z per vertex), optional normal, uv, color, and an optional index list that reuses vertices for triangles.

Noise: structured randomness

Math.random() gives static. Noise (Perlin/simplex/value) gives smooth, continuous randomness: nearby inputs give nearby outputs. Layer it at multiple scales (fractal Brownian motion, fBm) for natural-looking terrain, clouds and rock.

Live: noise terrain with controls

This builds a grid, displaces vertices by fBm, colors by height, and lets you tweak parameters. (Needs internet for Three.js and lil-gui.)

Instancing: thousands of objects, one draw call

Techniques catalogue

TechniqueUse
Seeded PRNG (mulberry32, alea)Reproducible worlds: same seed → same result; share "seeds" with users and for tests
Poisson-disc samplingEvenly spaced random points (trees, props) without clumps
Domain warpingFeed noise into noise for swirly, organic shapes
L-systemsPlants and fractals from rewriting rules
Marching cubes / dual contouringVoxel or implicit surfaces: caves, metaballs, Minecraft-like smooth terrain
Wave function collapseTile-based level and city layouts obeying constraints
Chunking + LODInfinite worlds: generate chunks around the player, drop distant ones, lower detail far away
Heightmap texturesDo displacement on the GPU in a vertex shader; compute normals in the fragment shader
Web WorkersGenerate chunks off the main thread; transfer typed arrays back (“Workers, service workers, IndexedDB & PWAs”)
PerformanceGeneration can take hundreds of ms. Build in a Worker, show a loading state, reuse buffers, and update BufferAttributes in place instead of recreating geometry. Always dispose geometry you discard.

Exercises

  1. Build a custom BufferGeometry for a cube, a cylinder and a torus by hand (positions, indices, normals, UVs). Compare with the built-ins.
  2. Extend the terrain demo: add a water plane with transparency, snow above a threshold, and a "seed" text input that hashes strings to numbers.
  3. Scatter 3,000 trees with InstancedMesh using Poisson-disc sampling, rejecting steep slopes and underwater positions.
  4. Implement infinite terrain: generate 32×32 chunks around the camera in a Worker, add and remove them as you move.
  5. Generate a tree with an L-system and render branches as instanced cylinders.
  6. Replace CPU displacement with a heightmap texture and vertex shader displacement; compare frame times with 1M vertices.

Checkpoint

Why use fBm instead of one noise layer?One layer looks blobby. Summing octaves at doubling frequency and halving amplitude adds detail at every scale, like real terrain (mountains, hills, rocks).
Why index geometry?Indices let triangles share vertices, cutting memory and vertex processing compared with duplicating every corner.
