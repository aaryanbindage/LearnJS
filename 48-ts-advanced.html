Advanced types: generics, mapped & conditional

TypeScript's type system is a small programming language of its own: types can take parameters, loop over keys, make decisions, and even read text. You don't need this every day, but it's how libraries like React, zod and tRPC give you such precise types, and once you can read it, their error messages stop being scary. Every example is live; hover to see the results.

In this lesson you will

  • Get types from values and from other types: typeof, keyof, indexed access.
  • Transform every property of a type with mapped types.
  • Make decisions in types with conditional types and pull pieces out with infer.
  • Build string types with template literal types.
  • Prevent mix-ups with branded types, and extend other libraries' types.
  • Know when not to use any of this.

Conditional types: "if" for types

A conditional type picks one of two types depending on a check. It reads like a ternary: A extends B ? IfYes : IfNo, meaning "if A fits into B, then IfYes, otherwise IfNo".

When not to be clever

The most important section
  • Types are for people too. If a teammate can't understand a type in a minute, it costs more than it saves. A slightly looser type with a clear name often beats a perfect, unreadable one.
  • Prefer the simplest tool: a plain type, then a union, then a generic, then utility types. Conditional and template literal types are for library-level code.
  • Name intermediate types. Five small named types read better than one giant expression.
  • Watch the compiler. Deeply recursive types can slow your editor down. If hovering gets slow, simplify.
  • Types don't replace runtime checks at the edges of your app.

Recap

  • typeof value, keyof T, T[K], T[number]: get types from values and other types.
  • Mapped types { [K in keyof T]: ... } transform every property; as renames keys.
  • Conditional types A extends B ? X : Y, applied per member of a union; infer extracts parts.
  • Template literal types build string types: `btn-${Size}`.
  • Brands make structurally identical types incompatible; assertNever enforces exhaustive handling.
  • Use the simplest type that does the job.
