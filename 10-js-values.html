Variables: giving values a name

Programs need to remember things: a score, a username, the items in a cart. A variable is how a program remembers. This is the most important idea in the lesson, so we'll take it slowly.

In this lesson you will

  • Create variables with let and const, and know which one to choose.
  • Change a variable's value, and use it to calculate new values.
  • Name variables well.
  • Meet the basic kinds of values: numbers, strings, booleans, undefined and null.

About 40 minutes.

What is a variable?

A value is a piece of data: the number 42, the text "Ada". A variable is a name that points to a value, so you can use it later.

AnalogyPicture a labelled box. The label on the outside is the variable's name, like score. The thing inside is its value, like 10. Whenever your program says score, the computer looks in that box and uses whatever is inside.

Let's read that first line word by word:

  • let: "I'm making a new variable."
  • score: the name we chose for it.
  • =: "put this value in it". In code, = does not mean "equals" like in math. It means assign: take the value on the right and store it under the name on the left.
  • 10: the value.

Then console.log(score) prints the value inside score. Notice there are no quotes around score. With quotes, it would print the word "score" instead of its value. Try it: change the line to console.log("score"); and run it.

const: a variable that can't be changed

The other way to make a variable is const (short for constant). It works just like let, except you can never assign a new value to it.

Why would you want a variable you can't change? Because most values in a program shouldn't change once they're set. If you mark them const and then accidentally try to change one, JavaScript stops you with an error instead of letting the bug slip through quietly.

The ruleUse const by default. Switch to let only when you know the value needs to change, like a counter or a score.

And var?

You'll see a third keyword, var, in older code and tutorials. It's the original way to make variables, from before let and const existed (2015). It has some confusing behaviour, so modern code doesn't use it. You can read it as "an old let", but don't write it.

Naming variables

You can pick almost any name, but there are rules, and there are good habits.

Rules (break these and you get an error):

  • Names can contain letters, digits, _ and $, but can't start with a digit. player1 is fine; 1player isn't.
  • No spaces or dashes. first name and first-name don't work.
  • You can't use words JavaScript has reserved for itself, like let, const, if or return.

Habits (everyone follows these, so you should too):

  • Use camelCase for multi-word names: start lowercase, then capitalize each new word: firstName, totalPrice, isLoggedIn.
  • Choose names that say what the value means. secondsLeft is far better than s or x.
  • A value that is truly fixed for the whole program is often written in UPPER_SNAKE_CASE: const MAX_PLAYERS = 4;

The kinds of values

Every value has a type: what kind of thing it is. The type decides what you can do with it. You can multiply numbers, but not words. These are the ones you'll use constantly:

Common mistakes
  • Using a variable before creating it. Code runs top to bottom, so console.log(total); let total = 5; fails: on the first line, total doesn't exist yet.
  • Writing let twice for the same name. let a = 1; let a = 2; is an error. Create once, then just use a = 2.
  • Quoting a variable name. console.log("total") prints the word "total", not its value.
  • Different capitals. userName and username are two different variables.

Recap

  • A variable is a named box holding a value. = means "store this value", not "is equal to".
  • const can't be reassigned, let can. Default to const. Don't use var.
  • x += 5, x -= 1, x++ are shortcuts for updating a value.
  • Name things in camelCase, and make names describe what they hold.
  • Basic types: number, string, boolean, undefined, null. Check with typeof.
