Meet TypeScript

TypeScript is JavaScript plus a safety net. You write the same code you've been writing, and add small labels that say what type each value should be. Then TypeScript checks your whole program for mistakes before it runs.

In this lesson you will

  • Understand what TypeScript is and why most professional JavaScript is now written in it.
  • Add your first type annotations: number, string, boolean.
  • Learn how TypeScript infers types so you don't have to write them everywhere.
  • Read TypeScript error messages, and learn how the TypeScript editors on this site behave.

In plain English: "You told me age holds a number, but you're trying to put a string in it." That's the whole idea of TypeScript. You state what you intend, and it checks that the code matches.

What TypeScript actually is

  • TypeScript is JavaScript with types added. Every JavaScript program is already valid TypeScript (TypeScript may just warn you about it). Everything you learn about JavaScript in this course applies to TypeScript too.
  • Browsers can't run TypeScript directly. A tool first checks your code, then removes the types, leaving plain JavaScript that runs anywhere. This step is called compiling (or "transpiling").
  • Types only exist while you're writing code. Once the code runs, they're gone. TypeScript doesn't make your program slower or change what it does.
AnalogyThink of a spell-checker in a word processor. It underlines mistakes while you type, but the printed letter has no red lines on it. TypeScript is a spell-checker for the logic of your code: "this should be a number", "this might be empty", "that property doesn't exist".

TypeScript was created at Microsoft in 2012 and is now used by most large JavaScript projects. React, VS Code, and the majority of the job listings you'll see expect it.

Type inference: TypeScript can work it out

Here's the good news: you rarely need to write those annotations. If you give a variable a value when you create it, TypeScript works out the type from the value. This is called type inference.

Hover over city on line 1 and you'll see let city: string. TypeScript saw the value "Lisbon" and decided city is a string for good. So the mistake on line 4 is caught, even though you never wrote a type.

When to write types yourself
  • Let TypeScript infer when you give a variable a value straight away. let count = 0; is clearer than let count: number = 0;.
  • Write the type when there's no value to infer from yet, like a variable you'll fill in later, and (in a few lessons) for function inputs.

Reading TypeScript errors

TypeScript errors can look intimidating at first, but most follow a few patterns. Here are the ones you'll see most in the beginning:

ErrorWhat it means
Type 'X' is not assignable to type 'Y'You're putting an X where a Y belongs. ("Assignable" means "allowed to be stored in".)
Cannot find name 'x'Nothing called x exists. Usually a typo, or you forgot to create it.
Property 'x' does not exist on type 'Y'You used .x on something that doesn't have an x.
Cannot assign to 'x' because it is a constantYou tried to change a const.

A good habit: read the error from the end. "Type 'string' is not assignable to type 'number'" ends with what TypeScript expected (a number). Then look at what you actually gave it (a string).

any: switching the checker off

Recap

  • TypeScript = JavaScript + types. It checks your code before it runs, then the types are removed.
  • Annotate with a colon: let score: number = 0;. Basic types: string, number, boolean.
  • Inference: if you give a value immediately, TypeScript works out the type. Hover to see it.
  • A const gets a literal type: the exact value itself.
  • Error messages say what was expected and what you gave. Read them from the end.
  • Avoid any, which switches checking off.

Check your understanding

Do types exist when the code runs?No. TypeScript checks the code, then removes all the types. The browser only ever runs plain JavaScript.
When should you write a type annotation on a variable?When TypeScript can't infer one, usually because there's no starting value. If you give a value right away, let TypeScript infer the type.
