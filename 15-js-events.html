Events: reacting to the user

A web page isn't much use if it can't respond. Clicks, key presses, typing in a box, submitting a form: each of these is an event, and your code can listen for them. By the end of this lesson you'll build a working to-do list.

In this lesson you will

  • Run code when something happens, with addEventListener.
  • Use the event object to find out what happened.
  • React to typing, and handle form submissions properly.
  • Handle clicks on many items with one listener (event delegation).
  • Run code later, or repeatedly, with timers.
  • Use TypeScript's event types, and safely narrow event.target.

Bubbling and event delegation

When you click an element, the event doesn't just happen on that element. It then travels up through every parent: the <li>, then the <ul>, then the <body>, and so on. This is called bubbling.

Bubbling enables a very useful trick. Instead of adding a listener to every item in a list (including ones that don't exist yet), add one listener to the list, and check which item was clicked. This is called event delegation:

closest("li") walks up from the clicked element to the nearest <li>. This matters when list items contain other elements, like a button inside the <li>.

Common mistakes
  • Calling the handler instead of passing it: addEventListener("click", sayHi()) runs sayHi once, immediately. Write addEventListener("click", sayHi).
  • Forgetting preventDefault() on form submit: the page reloads and your changes vanish.
  • Typos in event names: "onclick" or "Click" silently never fire. It's "click".
  • Adding listeners inside render(): every render adds another listener, so one click runs the code many times. Add listeners once, or use delegation.

Recap

  • el.addEventListener("click", handler) runs handler every time the event happens.
  • The handler receives an event object: e.target, e.key, e.preventDefault()…
  • Handle forms with the submit event, call preventDefault(), and read fields with FormData.
  • Events bubble up to parents, so one listener on a list can handle all its items (delegation, with closest).
  • setTimeout runs code once later; setInterval repeats until clearInterval.
  • TypeScript infers MouseEvent, KeyboardEvent etc. e.target is EventTarget | null: narrow with instanceof, or use the element you already have.

Check your understanding

What does preventDefault() do on a form's submit event?It stops the browser's default action: sending the form and reloading the page. Your JavaScript handles the data instead.
What is event delegation?Putting one listener on a parent element, and using e.target (often with closest) to work out which child was clicked. It also works for children added later.
Why can't you use e.target.value directly in TypeScript?e.target has the general type EventTarget | null, which has no value. Narrow it with instanceof HTMLInputElement first.
