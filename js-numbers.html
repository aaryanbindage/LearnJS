Numbers & math

Almost every program does some math: totals in a shopping cart, a timer counting down, a character moving across a screen. This lesson covers everything you need to work with numbers, including a few surprises.

In this lesson you will

  • Use the arithmetic operators, including remainder (%) and power (**).
  • Control the order of calculations with parentheses.
  • Round numbers, find the biggest or smallest, and make random numbers with Math.
  • Turn text like "42" into a real number, and understand NaN.
  • See how TypeScript stops you doing math on things that aren't numbers.

About 40 minutes.

The arithmetic operators

An operator is a symbol that does something to values. You already know most of these from school; only the symbols are a little different:

OperatorMeaningExampleResult
+add7 + 29
-subtract7 - 25
*multiply7 * 214
/divide7 / 23.5
%remainder7 % 21
**to the power of7 ** 249

JavaScript has just one number type for both whole numbers (integers, like 7) and decimals (like 3.5). Dividing two whole numbers gives you a decimal if it doesn't divide evenly.

The remainder operator %

% is the one most beginners haven't seen. It gives you what's left over after dividing. 7 divided by 2 is 3 with 1 left over, so 7 % 2 is 1.

AnalogyYou have 17 cookies to share among 5 friends. Each friend gets 3 (that's 15 cookies), and you have 2 left over. 17 % 5 is 2.

It sounds niche, but it's used everywhere. The most common use: a number is even if dividing by 2 leaves nothing over.

What is 20 % 6?

6 goes into 20 three times (18), leaving 2. So 20 % 6 is 2.

Order of operations

JavaScript follows the same order as school math: ** first, then * / %, then + -. Anything in parentheses happens first.

TipWhen in doubt, add parentheses. They make your intention obvious to the next person who reads the code, even when they're not strictly needed.

Decimals aren't always exact

You'd expect 0.3, but you get 0.30000000000000004. This isn't a JavaScript bug. Computers store numbers in binary (ones and zeros), and some decimals like 0.1 can't be stored exactly in binary, just like 1/3 can't be written exactly in decimal (0.3333…). Almost every programming language does the same thing.

Money tipFor prices, many programs store whole cents instead of decimals (1999 instead of 19.99) and only divide by 100 when displaying. Whole numbers are always exact.

Turning text into numbers

Values that come from the outside world, like what someone types into a form, almost always arrive as strings, even if they look like numbers. That causes a famous problem:

What if the text isn't a number at all?

NaN stands for "Not a Number". It's JavaScript's way of saying "I tried to make a number, but this didn't make sense". Any math with NaN gives NaN, so one bad value can spread through a whole calculation. Check for it with Number.isNaN():

One more oddity: dividing by zero doesn't crash. It gives Infinity.

Common mistakes
  • Doing math on strings from a form. "5" + 5 is "55". Convert with Number() first.
  • Forgetting parentheses in averages and percentages: a + b / 2 isn't the average of a and b.
  • Comparing decimals exactly. 0.1 + 0.2 === 0.3 is false. Round first, or work in whole numbers.
  • Doing more math on the result of toFixed(), which is a string. Round only at the very end, for display.

In TypeScript

All of this works the same in TypeScript, and every number, whole or decimal, has the type number. The difference is that TypeScript stops the "math on the wrong type" bugs before they happen.

The error on the last line says The left-hand side of an arithmetic operation must be of type 'any', 'number', 'bigint' or an enum type. That's a long way of saying: "you can only multiply numbers, and label is a string". In plain JavaScript this would quietly give you a wrong answer or NaN.

What TypeScript does and doesn't catch

Notice that typed + 1 is not an error, because joining a string and a number is a legitimate thing to want. But hover over b and you'll see its type is string, not number. TypeScript always tells you the truth about what you've got. If you then tried to use b as a number, it would complain.

Recap

  • Operators: + - * /, % (remainder) and ** (power). Use parentheses to control order.
  • Decimals can be slightly inexact (0.1 + 0.2). Round for display with toFixed(), which returns a string.
  • Math.round/floor/ceil, Math.max/min, Math.random() are your everyday helpers.
  • Convert text to numbers with Number(). Invalid conversions give NaN; check with Number.isNaN().
  • TypeScript blocks math on non-numbers, and hovering shows exactly what type you have.
