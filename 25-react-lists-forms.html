Lesson 25 — Lists, conditionals & forms

The everyday patterns of React UIs: rendering collections, showing and hiding, and handling real forms.

Conditional rendering

null, undefined, false and true render nothing. A lookup object is cleaner than a long chain of ternaries: { idle: <Idle/>, error: <Err/> }[status].

Lists and keys

KeysUse a stable unique id as the key. Don't use the array index if the list can be reordered, filtered or inserted into, or React will mix up state between items. Keys aren't passed as props; they only help React match items between renders.

Forms done right

  • Controlled inputs (value + onChange) give instant validation and formatting.
  • Uncontrolled inputs read values on submit: new FormData(e.target) or a ref. Simpler for big forms.
  • Validate on blur and submit, not on every keystroke from the start.
  • For large forms use libraries: React Hook Form + Zod.
  • React 19 adds form actions: <form action={fn}> with useActionState and useFormStatus.

Exercises

  1. Build a searchable, sortable product list (text filter, category select, sort by price).
  2. Build a multi-step form wizard (3 steps) with Back/Next and a summary.
  3. Build a login form with loading, error and success states, using one status state.
  4. Build a dynamic form where users can add and remove rows of fields (each row has an id).
  5. Demonstrate the "index as key" bug: a list with inputs inside, where you insert at the top.
  6. Add pagination (10 per page) to a list of 100 generated items.

Checkpoint

Why can't I use Math.random() as a key?It changes every render, so React treats each item as new and destroys/recreates its DOM and state. Keys must be stable.
Controlled vs uncontrolled?Controlled: React state drives the input's value. Uncontrolled: the DOM holds the value and you read it when needed.
