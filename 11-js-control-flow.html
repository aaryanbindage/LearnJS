Making decisions: if, else & switch

So far every program has run every line, top to bottom. Real programs need to choose: show the "Log in" button or the user's name; say "You win!" or "Try again". This lesson teaches your code to make decisions.

In this lesson you will

  • Run code only when a condition is true, with if.
  • Choose between two or more paths with else and else if.
  • Write short either/or values with the ternary operator ? :.
  • Pick from many fixed options with switch.
  • See how TypeScript makes sure a variable gets a value on every path.

About 45 minutes.

The if statement

An if statement runs a block of code only when a condition is true. Here's the shape:

  • The condition goes in parentheses. It's any question that gives a boolean, like the comparisons from the last lesson.
  • The code to run goes between curly braces { }. The code inside the braces is called a block.
  • The code inside is indented (pushed right by two spaces). JavaScript doesn't require this, but it makes it easy to see what's inside the block. Always do it.

else if: more than two paths

For three or more options, chain conditions with else if. JavaScript checks them in order, from the top, and runs the first one that's true. Then it skips the rest.

Let's trace it with score = 82:

  1. Is 82 ≥ 90? No. Move on.
  2. Is 82 ≥ 80? Yes! Print "Grade: B" and stop. The remaining checks are skipped.

You might wonder why the B check doesn't also need "and less than 90". It doesn't, because we only reach it if the A check already failed. That's why order matters.

If we swapped the order so score >= 70 was checked first, what grade would a score of 95 get?

95 ≥ 70 is true, so the first block runs and prints C. The A check is never reached. With else if chains, put the most specific (here, the highest) condition first.

switch: choosing from a list of exact values

When you compare one value against many exact options, a switch can be tidier than a long else if chain:

  • switch (day) says which value to look at.
  • Each case "...": is one possible value, checked with ===.
  • break means "done, leave the switch". Without it, the code keeps running into the next case, which is a classic bug.
  • Two cases stacked together (Saturday and Sunday) share the same code.
  • default: runs if nothing matched, like a final else.
Try itDelete the break; under "Almost the weekend." and set day to "Friday". Run it. Both messages print, because without break the code "falls through" to the next case.
Common mistakes
  • A semicolon after the condition: if (x > 5); { ... }. The ; ends the if immediately, so the block always runs.
  • = instead of === in a condition: if (score = 100) sets the score instead of checking it.
  • Wrong order in an else if chain: put the most specific condition first.
  • Forgetting break in a switch.
  • Missing braces: if (x) doA(); doB(); only makes doA conditional. Always use braces.

In TypeScript

if, else, ternaries and switch are written exactly the same in TypeScript. What TypeScript adds is checking that your decisions make sense.

Every path must give a value

Recap

  • if (condition) { ... } runs a block only when the condition is truthy.
  • else handles the false case; else if adds more options, checked top to bottom, first match wins.
  • Variables made inside { } only exist inside them (block scope).
  • condition ? a : b picks one of two values.
  • switch compares one value to many exact cases. Don't forget break.
  • TypeScript checks every path sets your variables, and flags cases that can never match.
