Lesson 2 — Links, images, media & semantic layout

Connect pages, embed media responsibly, and structure a page with landmarks that people and machines understand.

Links

  • Absolute URLs include the full address. Relative ones start from the current file.
  • Use rel="noopener" with target="_blank".
  • Link text must make sense alone: "Read the docs", not "click here".

Images

  • alt is mandatory. Decorative image: alt="".
  • width and height reserve space and prevent layout shift. loading="lazy" defers offscreen images.
  • Formats: SVG (icons, logos), WebP/AVIF (photos), PNG (lossless), JPG (photos).

Semantic layout

Landmarks let screen reader users jump straight to main or nav, help search engines parse structure, and make code self-documenting. Use exactly one <main> per page.

ElementUse for
header / footerIntro or closing content of page or section
navMajor navigation blocks
mainThe page's unique content
articleSelf-contained piece (post, card, comment)
sectionThematic group, normally with a heading
asideTangential content

Exercises

  1. Build a 3-page site (index, about, contact) with a shared <nav> and working relative links.
  2. Add an image with a proper alt, width, height and a figure caption.
  3. Add an in-page table of contents that jumps to sections via #id.
  4. Rewrite a page built from <div>s using only semantic elements.
  5. Open DevTools → Elements → Accessibility to confirm your landmarks appear.
