Booleans & comparisons

Programs constantly ask yes-or-no questions. Is the password long enough? Is the player out of lives? Is it the weekend? The answers are true or false, and this lesson is about asking those questions. It sets you up for the next lesson, where programs start making decisions.

In this lesson you will

  • Use the boolean values true and false.
  • Compare values with ===, !==, <, >, <=, >=.
  • Combine questions with AND (&&), OR (||) and NOT (!).
  • Understand "truthy" and "falsy" values, and why to avoid ==.
  • See how TypeScript catches comparisons that can never be true.

About 35 minutes.

Booleans

A boolean is the simplest type there is. It has exactly two possible values: true and false. (It's named after George Boole, a mathematician who worked out the logic of true and false in the 1800s.)

Notice there are no quotes. true is a boolean; "true" is a string that happens to contain the word true.

Naming tipBoolean variable names usually read like a yes/no question: isOpen, hasAccount, canEdit, shouldSave. When you read if (isOpen) later, it sounds like English.

Comparisons produce booleans

You'll rarely type true or false directly. Most booleans come from comparing values. A comparison asks a question and the answer is a boolean:

OperatorQuestion it asksExampleAnswer
===Are these equal?5 === 5true
!==Are these different?5 !== 3true
>Is the left bigger?5 > 3true
<Is the left smaller?5 < 3false
>=Bigger, or equal?5 >= 5true
<=Smaller, or equal?4 <= 3false

One, two or three equals signs?

This is the single most important thing in this lesson:

  • = (one) assigns: "put this value in this variable".
  • === (three) compares: "are these two values equal?"
  • == (two) also compares, but in a sloppy way. Don't use it. You'll see why below.

What does console.log(10 === "10") print?

=== checks that the values are equal and the same type. 10 is a number and "10" is a string, so they're not equal.

Combining questions: AND, OR, NOT

Real questions often have more than one part: "Is the user logged in and an admin?" There are three logical operators for this.

AND: &&

a && b is true only when both sides are true.

OR: ||

a || b is true when at least one side is true. (The | key is usually above Enter, with Shift.)

NOT: !

! flips a boolean: true becomes false, false becomes true.

With const x = 7, what is x > 5 && x < 10?

Both parts are true: 7 is more than 5, and 7 is less than 10. This is the standard way to ask "is x between 5 and 10?". (Writing 5 < x < 10 like in math does not work in JavaScript.)

Truthy and falsy

JavaScript lets you use any value where it expects a boolean. When it does, it treats the value as either "true-ish" (truthy) or "false-ish" (falsy). You only need to remember the short list of falsy values. Everything else is truthy.

Why not ==?

The two-equals == tries to convert values to the same type before comparing. The rules for that are so complicated that even experts get them wrong:

The ruleAlways use === and !==. If you need to compare a string to a number, convert one of them yourself first (like Number(input) === 10), so it's obvious what's happening.
Common mistakes
  • Using = when you meant ===. if (score = 10) sets score to 10 instead of checking it.
  • Math-style ranges. 1 < x < 10 doesn't do what you think. Write x > 1 && x < 10.
  • Repeating the variable in OR. day === "Sat" || "Sun" is always truthy, because "Sun" on its own is a non-empty string. Write day === "Sat" || day === "Sun".
  • Comparing against "true". isOpen === "true" compares a boolean to a string, so it's always false.

TypeScript catches impossible comparisons

Comparing values of types that can never be equal is almost always a bug. TypeScript points it out:

The message is This comparison appears to be unintentional because the types 'number' and 'string' have no overlap. "No overlap" means there's no value that could be both, so the answer would always be false. In JavaScript you'd only find this by testing; TypeScript finds it as you type.

The "repeated variable" mistake, caught

Remember day === "Sat" || "Sun" from the mistakes box? TypeScript notices too. Hover over isWeekend:

Its type is true | "Sunday", not boolean. That odd type is the clue that something's wrong: the expression can produce the string "Sunday". You'll learn what the | means in a later lesson on union types. For now, the habit to build is: if a type looks strange when you hover, look closer at the code.

Recap

  • A boolean is true or false. Comparisons produce booleans.
  • Compare with ===, !==, <, >, <=, >=. Never use ==.
  • && = both true, || = at least one true, ! = flip.
  • Falsy: false, 0, "", null, undefined, NaN. Everything else is truthy.
  • TypeScript flags comparisons between types that can never be equal.
