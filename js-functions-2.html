Arrow functions, scope & callbacks

In JavaScript, a function is a value, just like a number or a string. You can store it in a variable and pass it to another function. That one idea unlocks most of modern JavaScript: array methods, event handlers, React. This lesson builds it up step by step.

In this lesson you will

  • Store functions in variables, and write them with the short arrow syntax.
  • Understand scope: which variables a piece of code can see.
  • Pass a function into another function (a callback).
  • Meet closures: functions that remember where they were made.
  • Write function types in TypeScript.

About 50 minutes. If this feels abstract, that's normal. It will click when you use it in the array lessons.

Which style should you use? Both are fine and you'll see both everywhere. A common habit is function declarations for main, named functions, and arrows for short functions, especially ones passed to other functions (coming up next).

Scope: who can see which variables

Scope is the area of code where a variable exists. You've seen the rule already: variables made inside { } stay inside. The other half of the rule is that code inside can see out:

AnalogyScopes are like rooms with one-way windows. From inside a room you can see out into the hallway (outer scopes), but people in the hallway can't see into the room. A function inside a function is a room inside a room: it can see both outer rooms.

Because functions are values, you can pass one as an argument to another function. A function passed in like this is called a callback: the other function will "call it back" when it's ready.

Closures: functions that remember

Here's something surprising. A function can create and return another function. The inner function still has access to the outer function's variables, even after the outer function has finished:

makeCounter finished running on line 9, but the arrow function it returned still remembers count, and keeps updating it. A function bundled together with the variables it can see is called a closure. Each call to makeCounter creates a fresh count, so counter and other don't interfere.

Common mistakes
  • Braces without return in an arrow function: x => { x * 2 } returns undefined.
  • Calling instead of passing: setTimeout(sayHi(), 1000) runs sayHi immediately. Write setTimeout(sayHi, 1000).
  • Using an arrow function in a const before its line: only function declarations are hoisted.

Recap

  • Functions are values: store them in variables, pass them around.
  • Arrow functions: (a, b) => a + b. With braces you need return.
  • Scope: inner code can see outer variables; outer code can't see inner ones.
  • A callback is a function passed to another function. Pass it without ().
  • A closure is a function that remembers the variables from where it was made.
  • TypeScript function types look like (n: number) => string. Callback parameters are inferred from context.
